## Launch

Every driver package starts the same way; per-repo configuration (environment id, model path, port, baud rate, VISA resource) lives in the package's `driver.py`, never in launch flags:

```
mhs serve <driver-dir>
```

A package is done when `python3 -m mhs.driver check <driver-dir> --backend fake` exits 0 (evidence `contract_checked`; a fake never yields an MHS-Device level).

## Capability mapping

| native call | OpenMHS target | notes |
|---|---|---|
| Device(port=..., address=...) | lifecycle: the native backend factory in driver.py | construction and connection are never capabilities; addresses live in driver.py, not in launch flags |
| device.get_<quantity>() / device.<quantity> | @read: the measure class that fits (cap.measure.*), else cap.sensing.read.v1 | unit from the vendor documentation or the upstream code (UCUM); a read never changes the device revision |
| device.set_<parameter>(value) | @write: cap.device.configure.v1, or a write class that fits (cap.thermal.setpoint.v1, cap.imaging.illumination.v1) | every limit cites source and file:line, or is Limit.operator_required |
| device.move(...) / start() / acquire() | @action: the catalogue class that fits, else x-cap.<owner>.<name>.v1 with an inline schema | add a RESULT.json catalogue_requests entry for every x-cap id; declare long_running and cancellable for blocking calls |
| device.stop() / abort() / output_off() | @estop plus safe_state | the e-stop is mhs.safety.estop, not a capability |
| device.close() / disconnect() | lifecycle: driver teardown | never a capability (not self_test, not restore) |

Class ids come from `python3 -m mhs.driver catalog search <words>`. The deprecated classes cap.device.describe.v1, cap.world.state.v1, cap.world.snapshot.v1 and cap.world.restore.v1 are replaced by the protocol methods mhs.devices.get, mhs.resource.read, mhs.snapshot and mhs.restore.

## Safety

The risk floor of a device is the highest catalogue `risk_class` of its classes (CAP-017); a driver may declare a higher risk, never a lower one. Hardware at R1 or above needs an `@estop` and a non-empty safe state. Importability says nothing about hazards. Heaters, motors, pumps, lasers and high-voltage outputs are common; cite every limit from the vendor documentation or the upstream code, or use Limit.operator_required.

## Fidelity

A fake backend (a recording fake, or the upstream simulator when the repo ships one) yields contract_checked evidence only.

## Pitfalls

Constructors often open ports or start threads: keep them in the hardware backend factory. Optional heavy imports belong in the backend module. Do not claim capabilities from class names alone; confirm each native call in the code.
