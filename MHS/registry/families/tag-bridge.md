## Applicability

Devices a server exposes by register number, PV name or Alpaca member: triage rule 9, `family:tag-bridge`. The implemented `TagDriver` is a configuration-only helper with three profiles, `modbus`, `epics-ca` and `alpaca`: a finite `tag_config.points` table where every address carries `source_ref: path/in/clone:LINE` (or a bounded range) that shows it at the pinned commit, plus `parameters`, `reads`, `writes`, `commands`, `actions` and `safety_bindings`. `native` names the upstream class that shows the map; it is parsed, never imported. Gate G7 accepts a register only as the address argument of a Modbus call or as a register constant on the cited lines, with the call's table and direction matching the point. Read the [tag-bridge helper guide](../../sdk/docs/tag-bridge.md) for the grammar, the codecs and the transport interface, and copy the structure of the [labmastro exemplar](../../drivers/labs/josuablejeru__labmastro/driver.py) (a Modbus RTU bench supply: state reads, write-only setpoints with operator-required limits, confirmed output commands and a confirmed stop), never its registers, facts or limits.

Check the card's shape first. Triage files a repository here when it imports a tag library anywhere; when the device itself speaks serial, SCPI or a Python SDK and the tag protocol is only a service layer or an example (an OPC UA mailbox, a Tango or Lima plugin, a Modbus demo for another device), write that device's shape and record DEVIATION FROM THE CARD, or stop with blocked HELPER_MISSING. A repository whose PV names come from a deployment file absent from the clone cannot cite its addresses: stop.

## Capability mapping

| native call | OpenMHS target | notes |
|---|---|---|
| register, PV or Alpaca property read | `reads[field]` (resource state) or an observation command `{"read": {...}}`; cap.sensing.read.v1 only for a sensor kind | cite the line that shows the address; an x-cap observation declares `verb="read"` and takes no input |
| setpoint or configuration write | `writes[field]`: cap.device.configure.v1 | a sourced `Limit` or `Limit.operator_required`; a register's codec range is not a device limit; a write-only point shows the last acknowledged value |
| on/off, mode or start write sequence | `commands[capability]` with `steps`, `confirm` and `result` | fixed values or action inputs; confirmations are fresh reads; an x-cap.<owner>.<name>.v1 extension unless a catalogue class fits |
| Alpaca method (PUT) | `commands[capability]` with an `invoke` step | only the Alpaca errors that state no effect (0x400, 0x401, 0x407-0x409, 0x40B, 0x40C) are refusals; others, and a confirmation that does not hold, are unknown outcomes |

## Safety

The risk floor of a device is the highest catalogue `risk_class` of its classes (CAP-017); a driver may declare a higher risk, never a lower one. Hardware at R1 or above needs a declared native stop and a non-empty safe state. Any write or effectful command requires `safety_bindings["estop"]`: fixed writes or Alpaca methods followed by at least one confirmation read; R2+ hardware also needs an input-free `Action(safe_state=True)` with fixed steps and confirmation. Without a real, source-backed stop route a tag device may only observe (R0 reads). An acknowledgement alone never proves a stop, and a confirmation proves what the device reports, not physical quiescence: say in `safe_state` what stays energized or running.

Every TagDriver hardware backend, at every risk class and for every author, requires a schema-valid lock with a human `reviewed_by` entry of scope `hardware` before any factory or connection runs; models keep `reviewed_by` null. A lost, unacknowledged or unconfirmed write is an unknown outcome: the point leaves the state and ordinary effects are refused until a confirmed stop; a write-only setpoint whose write was lost then keeps commands refused until it is written again. Values a register cannot represent exactly are refused, never rounded. Industrial servers can front dangerous equipment; never write an undeclared tag.

## Fidelity

A `RecordingTagTransport` fake is a deterministic point store: it establishes only `contract_checked` evidence. Mark its seeded values as placeholders, model only the device behaviour the cited source shows (a written output read back), and say in RESULT.json notes what the fake does not model (regulation, timing, Modbus exceptions, server errors).

## Pitfalls

Address maps, unit ids and PV prefixes are deployment-specific; keep them in the backend options. Upstream helpers often scale, split or combine registers in ways the source must show (decimals, word order, two separate single-register writes are not one atomic value). Upstream code may swallow protocol errors; the package's transport must not. Multi-word writes, arrays, subscriptions and long-running commands are outside this helper version.
