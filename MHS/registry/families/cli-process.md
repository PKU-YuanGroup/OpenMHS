## Launch

Every driver package starts the same way; per-repo configuration (environment id, model path, port, baud rate, VISA resource) lives in the package's `driver.py`, never in launch flags:

```
mhs serve <driver-dir>
```

A package is done when `python3 -m mhs.driver check <driver-dir> --backend fake` exits 0 (evidence `contract_checked`; a fake never yields an MHS-Device level).

## Applicability

Repos the catalogue files as command-line tools. No Driver helper is planned before or after the pilot, so their cards are recon-only (wave 4) or last (wave 6: GPU, Windows or an engine licence). A simulator family needs a structural marker in the code, never only a README or name match.

## Capability mapping

No mapping is fixed for this family; recon cards decide per repo.

Class ids come from `python3 -m mhs.driver catalog search <words>`. The deprecated classes cap.device.describe.v1, cap.world.state.v1, cap.world.snapshot.v1 and cap.world.restore.v1 are replaced by the protocol methods mhs.devices.get, mhs.resource.read, mhs.snapshot and mhs.restore.

## Safety

The risk floor of a device is the highest catalogue `risk_class` of its classes (CAP-017); a driver may declare a higher risk, never a lower one. Hardware at R1 or above needs an `@estop` and a non-empty safe state. The risk floor of every class still comes from the catalogue.
