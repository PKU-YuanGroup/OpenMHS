## Applicability

Classic (synchronous) Ophyd Devices: triage rule 9, `family:ophyd`. `OphydDriver` is a configuration-only helper over the Python-object bridge. Each field is a `Field` in `parameters` plus one `signal_bindings` entry: `signal` (a direct Component attribute of the card's entry class), `get: True`, `set` (equal to `Field.writable`), `profile`, `get_kwargs`, `timeout_ms` (1..60000) and `source_ref` (the `path:LINE` of the Component assignment). Profiles: `classic_epics_v1` (`Component(EpicsSignal, ...)`: get, and a set that waits for its Status), `classic_epics_ro_v1` (`Component(EpicsSignalRO, ...)`: get only) and `classic_soft_v1` (`Component(Signal, ...)`, `get_kwargs` `{}`). Both EPICS profiles read with `get(use_monitor=False)` and require exactly that `get_kwargs`. Gate G7 proves each declaration in the pinned source without importing Ophyd, and refuses any other dotted member the fake or the driver touches (`OPHYD_UNPROVEN_MEMBER`).

The [apstools exemplar](../../drivers/labs/bcda-aps__apstools/driver.py) is a read-only R0 monitor: seven EpicsSignalRO fields of `ApsMachineParametersDevice`, one observational `x-cap` capability whose native is the proven `current.get`, a source-shaped fake and a hardware factory that builds the upstream Device. It shows the declaration grammar, the fake and the facts; it does not demonstrate a write, a Status or a native stop. The [Ophyd driver guide](../../sdk/docs/ophyd-driver.md) gives the complete contract.

## Capability mapping

| native call | OpenMHS target | notes |
|---|---|---|
| `Component(EpicsSignal, "PV")` | a `parameters` Field and a `signal_bindings` entry, `profile: classic_epics_v1` | a write calls `Signal.set` and waits for the returned Status within `timeout_ms`; raw `put` is never compiled; every numeric write cites a source line or is `Limit.operator_required` |
| `Component(EpicsSignalRO, "PV")` | a get-only binding, `profile: classic_epics_ro_v1` | a fresh `get(use_monitor=False)`; `set: True` is refused |
| `Component(Signal, ...)` (soft signal) | a binding with `profile: classic_soft_v1` | the value lives in the Python process, not in an IOC |
| a read-only Device | a capability: a catalogue read class that fits, else an `x-cap` read action (`commands` and `actions`) whose native is a bound `<signal>.get` | resource reads alone are not a capability; request the `x-cap` id in `RESULT.json` |
| `stop()`, `trigger()`, `stage()`, a positioner's `move()` | `commands`/`actions` or `safety_bindings`, only with source evidence of what the method does | a done Status does not prove that its callbacks ended; no exemplar demonstrates a native stop yet |
| EPICS engineering units | `Field(unit=...)` only when the source states the unit, else `unit_bindings` with an explicit operator option, or no unit | never infer a unit from a PV name |
| Device construction, `wait_for_connection()` | lifecycle: the `native.py` factory | the gate never imports it; PV prefixes are deployment data |
| nested Components, `FormattedComponent`, `DynamicDeviceComponent`, custom Signal classes, ophyd-async Devices | not expressible | G7 reports `OPHYD_COMPONENT_SOURCE` or `OPHYD_IDENTITY_UNRESOLVED`: stop `blocked` with the finding in the notes |

Class ids come from `python3 -m mhs.driver catalog search <words>`. The deprecated classes cap.device.describe.v1, cap.world.state.v1, cap.world.snapshot.v1 and cap.world.restore.v1 are replaced by the protocol methods mhs.devices.get, mhs.resource.read, mhs.snapshot and mhs.restore.

## Safety

The risk floor of a device is the highest catalogue `risk_class` of its classes (CAP-017); a driver may declare a higher risk, never a lower one. Hardware at R1 or above needs a native stop (`safety_bindings.estop`) and a non-empty safe state. Ophyd Devices front motors, shutters, detectors and high-voltage supplies: risk follows the hazard table of the safety specification, not the card's floor, and a model-authored R2 or R3 package never runs its hardware backend before a human signs `reviewed_by`. A Device's generic `stop()` is not evidence that anything physical stopped. EPICS drive limits, validators and PV metadata read at run time are not sourced limits.

## Fidelity

A source-shaped fake holds one stand-in object per bound Component that implements only the calls the driver makes (`get(use_monitor=...)`, and `set(value)` returning a Status for a writable binding); its values are placeholders and it runs no IOC. It yields `contract_checked` evidence only: Channel Access, PV connection and record processing are not modelled.

## Pitfalls

EPICS PV names are deployment-specific; area detectors produce large arrays (`NEEDS_ARTIFACTS`); startup-script profile collections are not Device classes. A class body with executable statements, decorators, metaclasses, reflection or receiver escapes fails the source proof even when its Components look simple.
