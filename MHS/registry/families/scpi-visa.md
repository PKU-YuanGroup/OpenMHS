## Capability mapping

| native call | OpenMHS target | notes |
|---|---|---|
| `*IDN?` | connect-time identity probe (`idn.expect`) | not a capability; identity is published by mhs.devices.get |
| measurement query (for example `MEAS:VOLT?`) | reads: cap.measure.voltage.v1 or the measure class that fits | parse to a number; the unit comes from the manual |
| setting (for example `FREQ <value>`) | writes: cap.device.configure.v1 | limits cite the manual or the upstream code |
| `*RST`, `INIT`, `ABOR` | lifecycle, or an action with a catalogue class | never a configure write |
| `SYST:ERR?` | error_query mapped to DriverFailed codes |  |
| output off / abort | safety_bindings: e-stop and safe state |  |

Class ids come from `python3 -m mhs.driver catalog search <words>`. The deprecated classes cap.device.describe.v1, cap.world.state.v1, cap.world.snapshot.v1 and cap.world.restore.v1 are replaced by the protocol methods mhs.devices.get, mhs.resource.read, mhs.snapshot and mhs.restore.

## Safety

The risk floor of a device is the highest catalogue `risk_class` of its classes (CAP-017); a driver may declare a higher risk, never a lower one. Hardware at R1 or above needs an `@estop` and a non-empty safe state. Sources, heaters, lasers and high-voltage supplies are common. Limits come from the instrument manual or the upstream code, never from the SCPI command name.

## Fidelity

A transcript or a pyvisa-sim device file checks the command map; it cannot validate a measurement.

## Pitfalls

SCPI carries no units; drain the error queue; one instrument per session; VISA backends differ (pyvisa-py versus a vendor VISA).
