## Applicability

Repositories whose device interface is an MCP server: triage rule 9, `family:mcp-client`. The implemented `McpClientDriver` is a configuration-only, finite tool contract over an injected controlled peer. It does not talk to a live MCP server: every non-fake backend refuses before any import, process start or connection, so a package passes on its fake (`contract_checked`) and states its native gaps in `RESULT.json` notes. Exemplar: [gh.mattjax16/rigol-dho-mcp](../../drivers/labs/mattjax16__rigol-dho-mcp/README.md) (thirteen tools of a Rigol oscilloscope server as sixteen bindings).

Configuration surface. `mcp_config["source"]` names one file, its SHA-256, the pinned commit and the decorator receiver. `mcp_config["tools"]` has one entry per selected tool: `input` (closed object schema; every array has `maxItems`, every free string `maxLength`), `output` (`kind` `json` with `schema`, `text`, or `png`, each with `max_bytes`), `effectful`, `source_ref`, `defaults`, and optionally `error_prefixes`, `result_matches` and `prerequisite`. Optional `safety` declares the protective transaction; `request_timeout_ms`, `stop_timeout_ms`, `max_message_bytes` and `owned_transport` bound the client. On the class: `commands` (every tool needs exactly one primary command; `arguments` and `select` add projections), an explicit `Action` per command whose inline output schema equals the tool's, `reads` with `parameters`, `mode = "hardware"`, and `backends = {"fake": ".fake:connect", "hardware": ".native:connect"}`. The fake returns a peer with `exchange(message, *, timeout_ms, lane)` that answers `tools/list` and `tools/call`; `native.py` refuses. No `writes`, `safety_bindings`, `safe_state=True` action, `estop_physical_ref` or method overrides; numeric inputs need a sourced or operator-required `Limit`. See [the MCP client guide](../../sdk/docs/mcp-client.md).

What it cannot express today: a hardware device at R2 or R3 (SAFE-045 wants a physical-stop reference or a safe-state action, and McpClientDriver allows neither), tools registered with `add_tool(...)` or through a low-level `Server` tool table (G7 proves literal decorators only), list or mixed content results (a JPEG preview beside metadata), tools that run caller-supplied code, and primary data the server itself drops before returning. Stop with blocked `HELPER_MISSING` or `NEEDS_ARTIFACTS` and name the source lines, or record a source-verified DEVIATION FROM THE CARD to another helper that matches the device's real interface.

## Capability mapping

| native call | OpenMHS target | notes |
|---|---|---|
| a tool registered by a literal `@<receiver>.tool()` on a top-level function of the pinned source file | one `mcp_config["tools"]` entry, one primary `commands[cap] = {"tool": name}` and an explicit `Action` | closed input schema from the signature, the literal default of every optional argument, `source_ref` inside the function; G7 proves name, arguments, defaults, file bytes and pin |
| a tool body that writes to the device, including select-then-query measurements | `effectful: true`; an `x-cap.<owner>.<tool>.v1` action unless a catalogue class has the same output | effects come from the body, never from the tool name, description or annotations |
| an argument-free read-only tool that returns a JSON object | `reads[field] = {"tool": ..., "path": ...}` beside its command | a read never replaces the tool's command |
| a numeric argument | `Limit(..., source="upstream_code", ref=...)` when the signature enforces it (`Field(ge=1, le=4)`), else `Limit.operator_required` | a docstring range or a description is not an enforced bound |
| a large JSON result or an MCP image | `output.artifact: true` (`artifact_ref`, `media_type`) or `kind: png` (`image_ref`, `width`, `height`, `media_type`) | the complete returned result; `array_counts` and `arrays_if` check array lengths |
| a documented precondition ("the scope must be stopped") | `prerequisite`: a fresh read-only observation with `path` and `equals`, cited inside the tool | refuses with PRECONDITION_UNMET; never performs the precondition itself |
| one argument whose unit depends on another | extra commands with `arguments` (`input`/`const`) or a cited `select` over one read-only observation | each binding declares its unit; the wire schema stays the source's |
| a stop tool plus a status readback | `mcp_config["safety"]`: `command`, `arguments`, `observe`, `path`, `equals` | the e-stop sends the command on the protective lane and needs a fresh matching observation after older requests retired |
| raw command, code execution, file path or URL tools | not exposed | no caller-supplied code, SCPI program, endpoint, credential or path |
| server start, transport, `tools/list` | lifecycle outside the package | discovery is a compatibility check, never authority; every non-fake backend refuses |

Class ids come from `python3 -m mhs.driver catalog search <words>`. The deprecated classes cap.device.describe.v1, cap.world.state.v1, cap.world.snapshot.v1 and cap.world.restore.v1 are replaced by the protocol methods mhs.devices.get, mhs.resource.read, mhs.snapshot and mhs.restore.

## Safety

The risk floor of a device is the highest catalogue `risk_class` of its classes (CAP-017); a driver may declare a higher risk, never a lower one. Hardware at R1 or above needs the `mcp_config["safety"]` protective transaction (it is the e-stop; `@estop` methods are not allowed) and a non-empty safe state; R2 and R3 cannot pass SAFE-045 with this helper today. Risk follows the device behind the server (MHS/spec/04-safety.md hazard table), never the tool names. Remote descriptions, titles and annotations are untrusted text and grant no authority. A successful-looking reply, MCP cancellation, a closed pipe or a process exit is not a device stop: the safe state is only the declared protective command plus a fresh matching observation, and an unconfirmed effect blocks new effects until an e-stop and reset settle it.

## Fidelity

A controlled peer yields `contract_checked` evidence only. The SDK's controlled profile is not FastMCP's native wire: FastMCP lists pydantic-generated schemas and can add `structuredContent` beside string results, which the bridge refuses; numbers in the fake are placeholders.

## Pitfalls

Tools named get_* can write (select, then query). One tool issues several device calls, so timeouts do not retire it. Error text often comes back as normal content (`error_prefixes`). Summaries can replace the primary array. Optional raw-command tools stay unexposed.
