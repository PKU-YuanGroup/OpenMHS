## Actions

### `move`

`x-cap.als-controls.bcs_move.v1` on `main`: invoke, risk R1, extension, cancellable.

Move the motor to a target in its configured unit: send MoveMotor, then poll fresh GetMotorFull state until Move Complete. Completed means the server reported Move Complete, not that the target was reached: a MoveMotor the server refuses is swallowed upstream and also ends completed; compare position with the target

Inputs:

| Field | Type | Unit | Required | Limit | Description |
|---|---|---|---|---|---|
| `target_position` | number | 1 | yes | operator required (not set) | Target in the motor's configured unit (the BCS configuration's Units), which the clone does not state; MHS requires a unit on a numeric input, and 1 stands for that unknown configured unit |

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `target_position` | number |  | The target that was sent, in the configured unit |
| `position` | number |  | Fresh Raw Motor Position observed when the move completed |
| `move_complete` | boolean |  | The fresh Motor State -> Move Complete at the last poll |

### `stop_motion`

`x-cap.als-controls.bcs_stop.v1` on `main`: invoke, risk R1, extension.

Stop the motor: send the native StopMotor command, then require two consecutive fresh GetMotorFull reports of Move Complete before reporting stopped

Inputs:

None.

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `stopped` | boolean |  | True only after two consecutive fresh Move Complete reports |
| `position` | number |  | Fresh Raw Motor Position observed when the stop was confirmed |

## Safety

- E-stop: software, latching, native stop `stop`.
- Safe state: No safe state is certified: the e-stop sends StopMotor and the stop action requires two fresh Move Complete reports, but StopMotor shares one REQ socket with the reads and moves, so an e-stop that cancels a move waiting for a GetMotorFull reply leaves the socket refusing every request: StopMotor never arrives and the motor finishes its commanded move; the e-stop reports SAFE_STATE_UNREACHED with the latch held (achieved by `x-cap.als-controls.bcs_stop.v1`).
- Operator-required limits not yet set: `move.target_position`. Hardware use is refused (MHS.SAFETY.LIMITS_UNSET) until site-limits.json supplies them.
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
