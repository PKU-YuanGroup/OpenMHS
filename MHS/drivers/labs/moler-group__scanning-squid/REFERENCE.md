## Safety

- E-stop: software, latching, native stop `atto.stop`, latency 5000 ms.
- Safe state: every Attocube axis stopped and grounded: stop(axis) sends 'stop n' and sets mode gnd (atto.py:143-152) for z, x and y, and the e-stop succeeds only when each axis mode reads back gnd (getm, atto.py:71-79); the piezo scanner is not stopped (its ramps cannot be) and keeps its voltage (achieved by `x-cap.moler-group.atto_ground.v1`).
- Operator-required limits not yet set: `step.steps`. Hardware use is refused (MHS.SAFETY.LIMITS_UNSET) until site-limits.json supplies them.
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.

## Facts

- A physical scanning SQUID microscope is represented by a Microscope or a subclass such as SusceptometerMicroscope, a QCoDeS Station of instrument components (vendor_doc: docs/pages/microscope.rst:4)
- SusceptometerMicroscope is the Microscope subclass for a scanning SQUID susceptometer and takes the configuration file and the temperature mode (upstream_code: scanning-squid/microscope/susceptometer.py:51-67)
- The Microscope constructor closes every QCoDeS instrument, loads the configuration, starts file logging and adds the Attocube controller, the Lakeshore 372 and 331, the scanner, the SQUID and the lock-ins (upstream_code: scanning-squid/microscope/microscope.py:78-121)
- The Attocube component is an ANC300 built from the configuration's atto entry (upstream_code: scanning-squid/microscope/microscope.py:123-134)
- Importing the microscope module writes squid_units.txt into the current directory (upstream_code: scanning-squid/microscope/microscope.py:62-69)
- approach steps the z Attocube by attosteps between capacitive touchdowns until a touchdown or a safety check breaks the loop (upstream_code: scanning-squid/microscope/microscope.py:314-339)
- The ANC300 axis mode parameter reads with getm n and writes with setm n; its values are gnd, inp, cap, stp, off, stp+ and stp- (upstream_code: scanning-squid/instruments/atto.py:71-79)
- The axis voltage parameter is limited to the configured voltage limit of the temperature mode (upstream_code: scanning-squid/instruments/atto.py:81-89)
- ask_raw clears the device, sends the command twice, raises if the second reply contains ERROR and sleeps 0.2 s (upstream_code: scanning-squid/instruments/atto.py:109-124)
- stop(axis) writes 'stop n' and then sets the axis mode to gnd (upstream_code: scanning-squid/instruments/atto.py:143-152)
- step(axis, steps) refuses a non-integer, sets mode stp, sends stepu or stepd with the axis and the step count, writes stepw, sleeps abs(steps)/frequency*1.25 s, sets mode gnd and records the move in its metadata (upstream_code: scanning-squid/instruments/atto.py:154-177)
- step sends its stepu or stepd command with ask, not write (upstream_code: scanning-squid/instruments/atto.py:168-169)
- _parse_axis accepts an axis label or controller index of the configured axes (upstream_code: scanning-squid/instruments/atto.py:185-209)
- Initialising the ANC300 sets each axis frequency and voltage to the configured values, grounds each axis and prints the controller version (upstream_code: scanning-squid/instruments/atto.py:305-319)
- The Scanner constructor moves the scanner to [0, 0, 0] (upstream_code: scanning-squid/scanner.py:51-61)
- get_pos reads the x, y and z scanner voltages with an NI-DAQ analog-input task and clamps each to the configured voltage limits (upstream_code: scanning-squid/scanner.py:109-131)
- goto writes a ramp to an analog-output task created inside the call and waits until it is done (upstream_code: scanning-squid/scanner.py:133-180)
- The documentation calls the approach the most dangerous part of a measurement: a missed touchdown crashes the SQUID into the sample using the Attocubes (vendor_doc: docs/pages/workflow.rst:34-38)
- The example configuration maps the Attocube axes x, y and z to controller axes 1, 2 and 3 (vendor_doc: docs/examples/config_susceptometer.json:49)
