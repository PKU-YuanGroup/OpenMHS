## Safety

- E-stop: software, latching, native stop `run action stop`, latency 10000 ms.
- Safe state: no protocol run of this endpoint executing: the e-stop sends the run action stop and reads the run's status until it is succeeded, stopped or failed (driver.py:175-181, 199-231); the robot's gantry, tips and liquids stay where the run left them (achieved by `x-cap.sciencecorp.ot2_stop_run.v1`).
- Operator-required limits not yet set: `run_protocol.protocol`. Hardware use is refused (MHS.SAFETY.LIMITS_UNSET) until site-limits.json supplies them.
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.

## Facts

- Ot2Driver keeps the robot address, the port (default 31950), the current run id, the base URL and the header Opentrons-Version: 2 (upstream_code: tools/opentrons2/driver.py:10-18)
- ping sends GET /health and raises unless the status code is 200 (upstream_code: tools/opentrons2/driver.py:20-30)
- upload_and_schedule_protocol posts the file as protocol.py to /protocols, then posts a run of that protocol to /runs and keeps its id as run_id (upstream_code: tools/opentrons2/driver.py:62-106)
- start_run posts the run action play to /runs/<id>/actions (upstream_code: tools/opentrons2/driver.py:108-123)
- pause_protocol and resume_protocol post the run actions pause and play for the current run (upstream_code: tools/opentrons2/driver.py:125-165)
- cancel_protocol posts the run action stop, then deletes the run, only logging a failed delete, and forgets the run id (upstream_code: tools/opentrons2/driver.py:167-197)
- get_run_status gets /runs/<id> with a 30 s timeout and returns the JSON body (upstream_code: tools/opentrons2/driver.py:199-214)
- wait_for_completion reads data.status every 2 s: succeeded ends it, and stopped, failed or blocked-by-open-door raise (upstream_code: tools/opentrons2/driver.py:216-241)
- close cancels an active run and only logs an error (upstream_code: tools/opentrons2/driver.py:308-315)
- No requests call of Ot2Driver other than get_run_status passes a timeout (upstream_code: tools/opentrons2/driver.py:20-197)
- ABCToolDriver answers any attribute it does not define with a function that returns None (upstream_code: tools/base_server.py:28-34)
- The OT-2 tool server's configure step leaves the Ot2Driver construction commented out, so its commands reach the ToolServer's ABCToolDriver (upstream_code: tools/opentrons2/server.py:24-27)
- The tool server's RunProgram writes the script with injected variables to a temporary file and runs it with start_protocol (upstream_code: tools/opentrons2/server.py:98-121)
- The pack's example OT-2 protocol loads a p300 single-channel pipette, picks up a tip and drops it (upstream_code: tools/opentrons2/protocols/example.py:86-89)
