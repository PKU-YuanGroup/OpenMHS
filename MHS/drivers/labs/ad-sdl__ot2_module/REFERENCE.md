`x-cap.ad-sdl.start_protocol.v1` on `main`: invoke, risk R2, extension.

Upload an Opentrons protocol file that the operator overlay allows, create a run and send the robot's play action; the run continues on the robot after this action returns, until it ends or is stopped, and the protocol alone decides what the robot does in it

## Safety

- E-stop: software, latching, native stop `send_request`.
- Safe state: Every run the robot lists as running, paused, finishing or in a status the clone's RunStatus does not name, and a new run of this driver whose play may be in flight, got the run stop action and then read stop-requested, stopped, succeeded or failed (stop-requested: the stop was accepted, motion may not have ended); a run stop over the HTTP API, not a hardware stop: it neither resets module set points nor stops anything outside a run, and no run is started (achieved by `x-cap.ad-sdl.stop_active_run.v1`).
- Operator-required limits not yet set: `start_protocol.protocol_path`. Hardware use is refused (MHS.SAFETY.LIMITS_UNSET) until site-limits.json supplies them.
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
