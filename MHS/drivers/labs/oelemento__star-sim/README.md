# Exemplar: gh.oelemento/star-sim (a PyLabRobotDriver profile)

The Hamilton STARlet digital twin of `oelemento/star-sim` (`star_sim.env:RobotEnv`, PyLabRobot on its ChatterBox
backend) as a simulated `PyLabRobotDriver`. It is the structural exemplar of the `pylabrobot` family. The package is
model-authored (`driver.lock.json` `authored_by` kind `model`) and unreviewed (`reviewed_by` null); its evidence is
`contract_checked` on the fake backend and never an MHS-Device level.

## Run the gate

```sh
PYTHONPATH=MHS/sdk/src python3 -m mhs.driver check MHS/drivers/labs/oelemento__star-sim --backend fake
```

## What it demonstrates

| Pattern | Where |
|---|---|
| A config-only `PyLabRobotDriver` with one `PlrProfile`: no methods, every runtime map generated | `driver.py` |
| The handler reached through the upstream object (`handler="lh"`) and its `setup`/`teardown` lifecycle | `plr_profile` |
| A declared labware allowlist, each name cited at the line that creates it | `labware=` |
| Self-contained `transfer` and `mix` operations (fresh tips from tip tracking, discard at the end) and the R0 `tracked_volumes` read | `operations=` |
| Bounds a pinned line states (`Limit(..., source="upstream_code", ref=...)`), one per operation at the tool that performs it | `PlrOperation(..., volume_limit=...)`, `cycles_limit` |
| A read-only parameter from an upstream getter (`tips.remaining`) | `parameters`, `reads` |
| A fake that keeps the upstream object's shape and composes the SDK's PyLabRobot model (`mhs.testing.pylabrobot`); every number in it is a placeholder | `fake.py` |
| Conformance inputs for pattern-constrained wells, with an alternate payload | `fixtures/conformance.json` |
| No native stop: the device is simulated and PyLabRobot `stop()` is teardown; the step in progress is not interrupted | `safe_state` |
| No cleanup motion after a failure: tips stay mounted and the endpoint is restarted to recover | `fidelity` gaps, `facts.md` |

## For a hardware PyLabRobot card

A hardware package keeps the same profile shape, sets `mode = "hardware"` and `risk = "R2"` (pipetting and
gantry motion, MHS-004 hazard table), puts the backend factory that builds the upstream `LiquidHandler` in
`native.py`, and marks every volume and cycle bound that no pinned line states `Limit.operator_required(...)`.
Without `plr_profile.stop` (a source-backed native stop that is not a teardown) the hardware backend is refused before
its factory runs and gate G3 refuses the package (`G3.NO_ESTOP`, SAFE-045): stop with `blocked` rather than invent a
stop. See `MHS/sdk/docs/pylabrobot-helper.md`.
