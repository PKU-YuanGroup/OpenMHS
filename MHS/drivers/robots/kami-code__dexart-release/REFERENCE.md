## Safety

- E-stop: software, latching, no native stop (software latch only).
- Safe state: the simulation stops advancing: after an e-stop the runtime's software latch refuses step, reset and seed until mhs.safety.reset clears it, the last world state stays readable, and no native stop method exists in a simulated environment (achieved by nothing declared).
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
