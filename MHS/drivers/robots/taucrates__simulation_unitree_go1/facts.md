## Scope

The package serves the simulated Go1's primary velocity control as one
`geometry_msgs/Twist` publication on `/cmd_vel`. The upstream launch names the
relative `cmd_vel` topic and includes the external yocs velocity smoother
(`go1_simulation/launch/velocity_smoother.launch:5-22`). The package also
serves one `sensor_msgs/LaserScan` read from `/scan`, the endpoint remapped in
`go1_simulation/launch/navigate.launch:14` and used by the move_base costmaps
(`go1_config/config/move_base/costmap_common_params.yaml:14`). The resource
snapshot is empty; no read is invented for a topic that a command can stop
publishing.

NOT COVERED: the depth camera images and point clouds, the IMU, odometry, TF,
the twelve joint controllers, contact sensors, move_base, AMCL, gmapping,
map_server and the Gazebo world stepping/reset. The launch and xacro files
name these surfaces, but this package does not bind them.

## Types and the G7 blocker

The pinned tree contains no `.msg`, `.srv` or `.action` file and no line that
spells a fully qualified ROS message type. The costmap YAML uses the short
names `LaserScan` and `PointCloud2`, but not `sensor_msgs/LaserScan` or
`sensor_msgs/PointCloud2`; the launch and xacro files name topics and Gazebo
plugins, not ROS types. The conventional `geometry_msgs/Twist` and
`sensor_msgs/LaserScan` names in `driver.py` are therefore not verified by the
upstream source, and gate G7 reports `ROS_TYPE_NOT_UPSTREAM` for both
bindings. This is a source-evidence blocker, not a fake limitation; no type or
type reference is represented as verified when it is not.

## Safety

The pinned tree exposes no ROS service or action that acknowledges a stop,
pause or reset. The `paused` launch argument in
`go1_simulation/launch/gazebo.launch:6,21` is a launch-time option forwarded
to the external `gazebo_ros` empty-world launch; it is not a runtime endpoint.
A zero-Twist publication is transmission only and is not an acknowledged stop.
The package declares `safety_bindings = {}` and no `safe_state=True` action.
The runtime's software latch refuses new commands, but it cannot prove that the
external CHAMP controller or Gazebo stopped; the stock e-stop reports
`MHS.SAFETY.SAFE_STATE_UNREACHED` and the package is recorded as blocked.

## Limits

The clone gives CHAMP gait maxima of 0.5 m/s forward, 0.25 m/s lateral and
1.0 rad/s yaw (`go1_config/config.json:197-202`, repeated in
`go1_config/include/gait_config.h:7-9`). Those are gait parameters of the
external controller and no negative bound or signed `/cmd_vel` envelope is
stated. Each command input therefore uses `Limit.operator_required`; the
runtime refuses an input until an operator overlay supplies the installed
bound. `site-limits.example.json` contains illustrative values only, marked as
such, and may only narrow.

## Fidelity contract

`driver.py` describes the deployed fake: engine
`analytic:ROS-free rosbridge contract stand-in (no Gazebo physics)`, level F0,
determinism `none`, `timestep_ms: 0` (event-driven, no physics step),
`realtime_factor: 0` (not paced), reset `none`, and no snapshot/restore. The
gaps disclose the absent Gazebo, gazebo_ros plugins, CHAMP controller, laser
sensor, depth camera and ROS graph; the placeholder scan sample and command
echo; the uncovered camera/IMU/odometry/TF surfaces; the missing acknowledged
stop; and the unverified message types. The fake's scan header carries the
ROS 1 fields `seq`, `stamp.secs`/`nsecs` and `frame_id`. The bridge refuses
non-finite numbers, so a scan with inf or NaN ranges is refused, never returned
with a substituted number (a package case covers it); whether the external
gazebo_ros laser plugin publishes such values is not shown in the clone. The
stock `test_gate` case keeps asserting a passing gate and therefore fails while
the package is blocked (model review, 2026-11-05).
