## Actions

### `publish_actuator_command`

`x-cap.isri-aist.actuator_command.v1` on `main`: invoke, risk R0, extension.

Publish one std_msgs/Float64 to the ActuatorCommand subscription. The plugin writes the value into d->ctrl once and leaves it there until another message arrives, so it stays the actuator's control input. The receipt proves only that rosbridge accepted the publication; it does not prove motion, target arrival or stopping.

Inputs:

| Field | Type | Unit | Required | Limit | Description |
|---|---|---|---|---|---|
| `value` | number | 1 | yes | operator required (not set) | Scalar written to d->ctrl for the configured actuator; the MJCF actuator type, scale and range are model configuration, so no numeric envelope is stated by the clone |

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `published` | boolean |  | True when the driver handed the publication to rosbridge |
| `confirmed` | boolean |  | Always false: a rosbridge publication carries no execution confirmation |
| `message` | object |  | The std_msgs/Float64 message handed to rosbridge; it does not prove native reception |
| `message.data` | number | 1 | Scalar written to the message data field |
