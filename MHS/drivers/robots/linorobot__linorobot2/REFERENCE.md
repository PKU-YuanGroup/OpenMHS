## Actions

### `publish_cmd_vel`

`x-cap.linorobot.cmd_vel.v1` on `main`: invoke, risk R2, extension.

Publish one geometry_msgs/Twist velocity setpoint to /cmd_vel for the gz-sim DiffDrive plugin. The receipt confirms only that rosbridge accepted the publication, not motion, arrival or stopping.

Inputs:

| Field | Type | Unit | Required | Limit | Description |
|---|---|---|---|---|---|
| `linear_velocity` | number | m/s | yes | operator required (not set) | Body-frame forward velocity written to twist.linear.x |
| `angular_velocity` | number | rad/s | yes | operator required (not set) | Body-frame yaw rate written to twist.angular.z |

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `published` | boolean |  | True when the driver handed the ROS message to rosbridge |
| `confirmed` | boolean |  | Always false: a rosbridge publication carries no execution confirmation |
| `sent_linear_velocity` | number | m/s | The linear.x handed to rosbridge (the transmitted request) |
| `sent_angular_velocity` | number | rad/s | The angular.z handed to rosbridge (the transmitted request) |

### `resume_simulation`

`x-cap.linorobot.resume.v1` on `main`: invoke, risk R2, extension.

The declared re-enable after a safety reset: publish a zero Twist on /cmd_vel, then unpause the world with a WorldControl request (pause false) on /world/turtlebot3_world/control. DiffDrive keeps the last Twist it received and applies it as soon as the world runs; the zero replaces it, but it is an unacknowledged publication, so a stored command can still act for a few world steps.

Inputs:

None.

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `acknowledged` | boolean |  | True once the world control request answered success |
| `zero_command_published` | boolean |  | True when the zero Twist was handed to rosbridge before the unpause; a transmission, not a confirmation |

## Safety

- E-stop: software, latching, native stop `/world/turtlebot3_world/control`, latency 1500 ms.
- Re-enable after a reset: `x-cap.linorobot.resume.v1` (the reset never runs it; it is refused while the e-stop is latched).
- Safe state: The world turtlebot3_world is paused: after the WorldControl pause two fresh stats samples, 40 ms or more apart within 600 ms, reported paused true, so the world does not step and the drive plugins apply no velocity; it is the paused flag in that window, not a measured standstill, it needs the operator-run ros_gz bridges, and the GUI, a WorldControl client or a step request can unpause or step the world. (achieved by nothing declared).
- Operator-required limits not yet set: `publish_cmd_vel.angular_velocity`, `publish_cmd_vel.linear_velocity`. Hardware use is refused (MHS.SAFETY.LIMITS_UNSET) until site-limits.json supplies them.
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
