## Safety

- E-stop: software, latching, native stop `/uav/motors_on`, latency 6000 ms.
- Sensed-confirmation stop (simulated devices only; SAFE-049): the request steps `/uav/motors_on` (topic) prove nothing by themselves. The e-stop is achieved only when every source (`/uav/gps` (nav_msgs/msg/Odometry, stamp `header.stamp`)) delivers 3 fresh samples, on subscriptions opened after the request, that satisfy every term below within 4000 ms of the first transmission; otherwise it fails `MHS.SAFETY.SAFE_STATE_UNREACHED`, the latch is kept and the background retry sends the request again. A reset re-confirms without a request.
- Sensed state: Bool false on /uav/motors_on, then three fresh /uav/gps samples with Gazebo-frame z at or below the operator's landed band and x, y and z still, inside the confirmation window; the publication proves nothing and the pose may already hold..
- Predicate: `gps.pose.pose.position.z <= landed_z.max`.
- Predicate: `max - min of gps.pose.pose.position.x over the window <= rest_x`.
- Predicate: `max - min of gps.pose.pose.position.y over the window <= rest_y`.
- Predicate: `max - min of gps.pose.pose.position.z over the window <= rest_z`.
- Threshold `landed_z.max` (max): operator_required (The clone states no Gazebo-frame landed height. landing_motor_cutoff_height -0.25 is an NED desired height, not a /uav/gps z bound, and the spawn z 0.2 is a start pose, so the operator supplies the band.).
- Threshold `rest_x` (max): operator_required (The clone states no at-rest bound. The p3d gaussian_noise 0.01 is sensor noise, not the largest position change that counts as still, so the operator supplies the span.).
- Threshold `rest_y` (max): operator_required (The clone states no at-rest bound. The p3d gaussian_noise 0.01 is sensor noise, not the largest position change that counts as still, so the operator supplies the span.).
- Threshold `rest_z` (max): operator_required (The clone states no at-rest bound. The p3d gaussian_noise 0.01 is sensor noise, not the largest position change that counts as still, so the operator supplies the span.).
- Publisher history of `/uav/gps` (a new subscription's replay, discarded before any sample counts): operator_required (The /uav/gps publisher is libgazebo_ros_p3d outside this clone. The URDF remaps odom to uav/gps and sets frame_name world, gaussian_noise 0.01 and update_rate 10, and it states no QoS. The README names Ubuntu 22.04 with ROS 2 Iron, and no Iron gazebo_ros companion is fetched.).
- Client execution bounds (no source: a wrong value can only withhold the confirmation): consecutive 3, min_span_ms 200, max_gap_ms 500, confirm_within_ms 4000.
- Safe state: Simulated only: Bool false on /uav/motors_on is confirmed only by three fresh /uav/gps samples with Gazebo z at or below the operator's landed band and x, y and z still within the operator's span; the Bool proves nothing, an already-landed pose can pass, and there is no motors-on command because ControlNode and TrajectoryNode keep their last mode, so recovery outside MHS must leave both at mode 0 before any Bool true, and stopping GuiNode alone does not clear that mode. (achieved by nothing declared).
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
