# ProjectAirSim live route: the five former adapter requirements

The selected route remains `ProjectAirSimDroneLandingEnv`: three NED velocity components per step, four pose/yaw observations, reward, episode status and reset. The earlier version of this file listed five requirements that blocked the package because the synchronous Gymnasium bridge never awaited `async def step` (`projectairsim_dronelanding_env.py:63-88`). The SDK now has an asynchronous profile (`asyncio_owned_loop_v1`) and the package declares it for both backends. This file records, for each requirement, what is settled by contract and what remains unproven. Nothing here was run against a Project AirSim server.

1. Partial construction. `gym_env.py:27-29` connects a client before constructing World. The live factory (`sim.py`, `construct`) disconnects a client that a failed constructor already connected, then re-raises. Package tests cover the unwind with stand-in classes. The environment is constructed on the caller's thread, outside the owned loop. Unproven: how long `client.disconnect()` blocks (it joins the receive thread without a bound, `client.py:419-424`).
2. The two-stage async step. One owned event loop awaits the coroutine step: the move request, the blocking `continue_for_sim_time` and the awaited move task all run on that loop, so the client is never entered from two threads. A step that exceeds its local bound is not cancelled locally; its outcome is unknown, it stays owned until it settles, new native work and safety reset are refused meanwhile, and an explicit world reset is required afterwards (fresh state, never the late result). Unproven: that the move task always completes within the commanded period on a real server.
3. Bounded admission, execution, cancellation and close. Every native call has a declared local bound (step 30 s, reset 120 s, close 15 s, stop and probe 5 s, settlement 10 s; package choices, not upstream facts). Cancellation is observed between native calls; no call is dispatched after an e-stop engaged. Close pauses the world, closes the environment on the loop and stops the loop, all bounded, and is deferred while native work is owned. The client's own service socket waits up to 300 s per request (`client.py:59-60`), so a bound can expire while the server still works; that case is reported unknown and owned, never success.
4. Reset. The native `reset()` loads the scene, creates the drone, subscribes, enables API control and arms (`:32-61`). It is effectful and runs only as a world reset (`cap.world.reset.v1`, or the implicit first reset before the first step), never as e-stop recovery. It takes no seed or options: no seed capability is served, no seeded determinism is claimed, and the reset input `seed` is accepted for the class contract only and not used.
5. Stop and terminal facts. The e-stop calls the declared remote stop `world.pause` (`world.py:114-126`; the server's SimPause applies to the steppable clock this scene declares, `scene.cpp:706-723`, `scene_bonsai_drone_landing.jsonc:14-19`) and reads it back with `world.is_paused` (`world.py:238-250`). The safe state is reported only when the pause returned, the probe returned exactly True and no native work is owned; otherwise the endpoint keeps the latch and retries. The episode ends on collision only (success TODO, line 85). The remote stop cannot interrupt the step's blocking `world.continue_for_sim_time` (`projectairsim_dronelanding_env.py:77-81`): it queues behind that call on the owned loop, the call ends by itself at its simulated-time bound with the clock paused (`scene.cpp:727-752`), and the pause and probe run afterwards. `world.is_paused` reads the scene clock's flag only (`scene.cpp:725`); SimPause does not wait for Unreal to confirm (`scene.cpp:711-712`). Unproven: the server's pause semantics while a move task is outstanding, and that no other client advances the clock.

Image, Sydney and perception variants remain separate unfinished scope. No native client, simulator, Unreal process or hardware was imported, installed or run; evidence is `contract_checked` on the fake.
