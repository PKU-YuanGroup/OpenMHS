## Actions

### `set_twist`

`x-cap.mrpt.mvsim_controller_twist.v1` on `main`: invoke, risk R2, extension.

Hand one twist setpoint (vx, wz) to the vehicle's controller through MVSim's set_controller_twist service; the setpoint persists until another command

Inputs:

| Field | Type | Unit | Required | Limit | Description |
|---|---|---|---|---|---|
| `vx` | number | m/s | yes | operator required (not set) | Linear velocity setpoint along the vehicle's local x axis |
| `wz` | number | rad/s | yes | operator required (not set) | Angular velocity setpoint about the vehicle's vertical axis |

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `accepted` | boolean |  | True when MVSim answered that the controller accepted the setpoint |
| `vx` | number | m/s | The linear velocity setpoint the controller accepted |
| `wz` | number | rad/s | The angular velocity setpoint the controller accepted |

## Safety

- E-stop: software, latching, native stop `set_controller_twist`.
- Safe state: MVSim's set_controller_twist accepted a zero twist setpoint for the configured vehicle's controller, under the simulation-step lock: zero velocity is commanded, not measured braking. A controller that does not accept twists refuses it (e-stop unreached). ROS cmd_vel, GUI teleop and other MVSim clients can still command it. (achieved by nothing declared).
- Operator-required limits not yet set: `set_twist.vx`, `set_twist.wz`. Hardware use is refused (MHS.SAFETY.LIMITS_UNSET) until site-limits.json supplies them.
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
