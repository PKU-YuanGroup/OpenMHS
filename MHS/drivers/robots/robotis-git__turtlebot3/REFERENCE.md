## Actions

### `publish_velocity`

`x-cap.robotis-git.cmd_vel.v1` on `main`: invoke, risk R2, extension.

Publish one geometry_msgs/TwistStamped velocity setpoint to the upstream cmd_vel topic; the receipt confirms only that rosbridge accepted the publication, not motion, arrival or stopping

Inputs:

| Field | Type | Unit | Required | Limit | Description |
|---|---|---|---|---|---|
| `linear_velocity` | number | m/s | yes | operator required (not set) | Body-frame forward velocity; the callback uses only twist.linear.x |
| `angular_velocity` | number | rad/s | yes | operator required (not set) | Body-frame yaw rate; the callback uses only twist.angular.z |

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `published` | boolean |  | True when the driver handed the TwistStamped to rosbridge |
| `confirmed` | boolean |  | Always false: a rosbridge publication carries no execution confirmation |

## Safety

- E-stop: software, latching, native stop `/motor_power`.
- Safe state: The acknowledged /motor_power std_srvs/SetBool service with data=false disables the OpenCR motor-torque enable register; this is a torque-disable acknowledgement only, not a brake, not a measured zero velocity and not a hardware emergency stop. (achieved by `x-cap.robotis-git.disable_torque.v1`).
- Operator-required limits not yet set: `publish_velocity.angular_velocity`, `publish_velocity.linear_velocity`. Hardware use is refused (MHS.SAFETY.LIMITS_UNSET) until site-limits.json supplies them.
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
