## Actions

### `publish_cmd_vel`

`x-cap.6-robot.cmd_vel.v1` on `main`: invoke, risk R2, extension.

Publish one geometry_msgs/Twist velocity setpoint on /cmd_vel. The WPRPlugin callback stores the components, also while the world is paused; the receipt is transmission evidence and the values sent, not motion or stopping.

Inputs:

| Field | Type | Unit | Required | Limit | Description |
|---|---|---|---|---|---|
| `linear_x` | number | 1 | yes | operator required (not set) | Twist linear.x component |
| `linear_y` | number | 1 | yes | operator required (not set) | Twist linear.y component |
| `angular_z` | number | 1 | yes | operator required (not set) | Twist angular.z component |

Outputs:

### `resume_simulation`

`x-cap.6-robot.resume.v1` on `main`: invoke, risk R2, extension.

The declared re-enable after a safety reset: publish a zero Twist on /cmd_vel, then unpause the Gazebo world with /gazebo/unpause_physics. WPRPlugin keeps the last cmd_vel it stored and applies it as soon as the world runs; the zero replaces it, but it is an unacknowledged publication, so a stored command can still act for a few world steps.

Inputs:

None.

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `acknowledged` | boolean |  | True once /gazebo/unpause_physics answered |
| `zero_command_published` | boolean |  | True when the zero Twist was handed to rosbridge before the unpause; a transmission, not a confirmation |

## Safety

- E-stop: software, latching, native stop `/gazebo/pause_physics`.
- Re-enable after a reset: `x-cap.6-robot.resume.v1` (the reset never runs it; it is refused while the e-stop is latched).
- Safe state: The Gazebo world is paused and get_physics_properties read pause true back: no world update runs, so WPRPlugin applies no force and /odom is silent; it is the paused flag, not a measured standstill, and it holds until the resume command, the Gazebo GUI or another client unpauses the world (a GUI step advances it), and the plugin keeps its stored cmd_vel, which the resume zeroes first without an acknowledgement. (achieved by nothing declared).
- Operator-required limits not yet set: `publish_cmd_vel.angular_z`, `publish_cmd_vel.linear_x`, `publish_cmd_vel.linear_y`. Hardware use is refused (MHS.SAFETY.LIMITS_UNSET) until site-limits.json supplies them.
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
