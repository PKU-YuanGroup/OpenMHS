## Actions

### `take_lapse_lock`

`x-cap.aurelienroy.take_lapse_lock.v1` on `main`: invoke, risk R0, extension.

Take the plugin's bounded wall-time lapse lock with the upstream method default horizon of 1 s; this pauses the plugin loop that steps the paused Gazebo world and exchanges packets with ArduPilot SITL, not ArduPilot itself, and the plugin clears the lock automatically when the timer expires

Inputs:

None.

### `release_lapse_lock`

`x-cap.aurelienroy.release_lapse_lock.v1` on `main`: invoke, risk R0, extension.

Release this driver's lapse lock; succeeds only when the returned holder count is zero, because a positive count means another holder still pauses the loop

Outputs:

## Safety

- E-stop: software, latching, native stop `/fdmUDP/take_apm_lapseLock`.
- Safe state: The acknowledged take_apm_lapseLock service holds the plugin's lapse lock with the maximum float32 horizon, so its loop stops exchanging SITL packets and stops stepping the Gazebo world it keeps paused: the aircraft is frozen while no client unpauses Gazebo. ArduPilot SITL keeps running, and any release that brings the shared holder count to zero resumes the loop, such as one by a holder whose own lock expired or by the parachute path. (achieved by nothing declared).
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
