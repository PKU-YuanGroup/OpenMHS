### `resume_simulation`

`x-cap.rigbetellabs.resume.v1` on `main`: invoke, risk R2, extension.

The declared re-enable after a safety reset: publish a zero Twist on /cmd_vel, then unpause the world with a WorldControl request (pause false) on /world/default/control. DiffDrive keeps the last Twist it received and applies it as soon as the world runs; the zero replaces it, but it is an unacknowledged publication, so a stored command can still act for a few world steps.

Inputs:

None.

Outputs:

| Field | Type | Unit | Description |
|---|---|---|---|
| `acknowledged` | boolean |  | True once the world control request answered success |
| `zero_command_published` | boolean |  | True when the zero Twist was handed to rosbridge before the unpause; a transmission, not a confirmation |

## Safety

- E-stop: software, latching, native stop `/world/default/control`, latency 1500 ms.
- Re-enable after a reset: `x-cap.rigbetellabs.resume.v1` (the reset never runs it; it is refused while the e-stop is latched).
- Safe state: The world default is paused: after the WorldControl pause two fresh stats samples, 40 ms or more apart within 600 ms, reported paused true, so the world does not step and DiffDrive applies no velocity; it is the paused flag in that window, not a measured standstill, it needs the operator-run ros_gz bridges, and the GUI, a WorldControl client or a step request can unpause or step the world. (achieved by nothing declared).
- OpenMHS is not a safety certification and not a safety-rated channel; the physical e-stop stays authoritative.
