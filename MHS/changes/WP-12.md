## What changed

- **Archive.** `review/`, `remediation/`, `remediation-round2/`, `verification/` and `reports/` were moved with `mv` into
  `_archive/audit-2026-10/` (nothing deleted). Before the move every reference in `MHS/`, `integration/` and the root files was
  checked: only a test that asserts the public documents do **not** mention those directories and one docstring named them.
  `_archive/README.md` maps old to new paths and lists the other archived material (`optimization-2026-10/`, the skeleton
  manifests, the duplicate SDK reports). The planning record of this optimization (plan, work packages, the 189 verified findings,
  decisions, follow-ups, the workflow scripts) is `_archive/optimization-2026-10/`.
- **Root `.gitignore` is an allowlist**: only `README.md`, the licence files, `SECURITY.md`, `CODE_OF_CONDUCT.md`,
  `CONTRIBUTING.md`, `CHANGELOG.md`, `.github/`, `tools/`, `MHS/` and `integration/` are tracked. `MHS/.gitignore` ignores the
  built `_site/`, caches, `.mhs-run/`, and the timestamped `check-report.json` that every gate run writes.
- **CI** (`.github/workflows/ci.yml`): `suites` (Python 3.10 and 3.14: generated data in sync, the interface contract is current,
  spec doctests, the SDK suite, registry tests/index/validate `--no-corpus`, `mhs.conformance verify` of every published report,
  a wheel built and used outside the checkout), `drivers` (exemplar and tutorial gates on freshly fetched pinned clones; for a pull
  request: one package only, nothing outside `MHS/drivers/`, the gate re-run, `collect.py --strict`; a committed `RESULT.json` is
  never trusted), `site` (build for a URL and `check.py --fresh`), `integration` (only when the repository variable
  `OPENAI4S_REPO` names an OpenAI4S checkout) and `export` (`tools/oss_export_check.py --skip-suites`).
- **`tools/oss_export_check.py`**: copies the allowlisted items to a temporary directory, lets a temporary git repository apply
  the real ignore rules and keeps exactly what a clone would contain; then asserts the allowlist, the required files, no CNAME, the
  non-affiliation statement at the top of the READMEs and the package description, no maintainer home or build-machine temporary
  path, no CJK text outside registry `x-vendor` fields and the registry's own code and tests (which parse the Chinese-language
  catalogue), no spelling of Anthropic's domain outside appendix D, the identifier module, history files, third-party registry
  records and tests that assert its absence. Without `--skip-suites` it also runs the suites inside the export (sync, SDK, registry
  `--no-corpus`, site build and check, the thermostat and exemplar gates, the OpenAI4S integration suite when a checkout exists),
  which proves that nothing depends on the private workspace.
- **`tools/fetch_clone.py`**: fetches one upstream repository at the card's pinned commit (shallow), so CI and contributors need
  not have the ~690 GB corpus. **`tools/build_changelog.py`** keeps the per-fragment index of `CHANGELOG.md` in step with
  `MHS/changes/`.
- **`CHANGELOG.md`**: a hand-written summary (behaviour changes first) and one generated section per change fragment.
- **Recorded artifacts regenerated** because they quoted Anthropic's domain in a device profile link: `MHS/sdk/docs/e2e-transcript.txt`
  (by `MHS/sdk/tests/core/_e2e_transcript.py`), `MHS/sdk/docs/reports/replay-bundle-conveyor.json` and the replay conformance report
  (by the commands in `MHS/sdk/docs/reports/README.md`; the report still verifies at CL2).
- Change fragments lost the maintainer's home path, temporary-directory paths and three Chinese phrases.
- Root and `MHS/` READMEs link the driver packages, the handoff kit and the tools; `MHS/sdk/README.md` no longer calls the generated
  `INTERFACE.md` a frozen interface.
