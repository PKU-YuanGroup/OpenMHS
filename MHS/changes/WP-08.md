### What changed

`MHS/sdk/src/mhs/mcp.py`:

- **Policy flags.** `MCPPolicy(operator_tools=False, allow_external_sessions=False)`,
  read from the settings document (only a JSON `true` enables a flag; this now
  also holds for `allow_hardware`) and from `--operator-tools` /
  `--allow-external-sessions` (enable only).  `mhs__reset` and `mhs__permit`
  (`OPERATOR_TOOLS`) are not listed and refuse with `MHS.AUTH.FORBIDDEN`
  (`policy: "operator_tools=false"`, `reason: "operator_tool"`) before any
  endpoint call, under every policy that does not set `operator_tools`.
- **Sessions.** Opened per (device, capability) with principal
  `{"kind": "agent", "id": "agent:mcp/<clientInfo.name>"}` (`agent_principal`),
  TTL 3600 s (`SESSION_TTL_S`).  Before a call, a heartbeat is sent when less
  than a third of the TTL is left.  `MHS.SESSION.EXPIRED`/`UNKNOWN`/`CLOSED`
  (from the heartbeat or the call) drops the session, opens a new one and
  returns `isError` (`session_renewed`, "this call was NOT executed ... re-read
  its state"); commands are never retried, reads are retried once.  A
  `session_id` argument the projection did not open is refused with
  `MHS.SESSION.UNKNOWN` unless `allow_external_sessions`.  `close()` closes
  every owned session.
- **Retry tokens.** `_meta.retryToken` (and `_meta.command_id`,
  `_meta.retry_token`) and a `command_id` that is not a ULID map to
  `retry_command_id(token, tool_name)`: the first 16 bytes of
  `sha256(tool_name + "\n" + token)` as a ULID.  A ULID `command_id` is used
  verbatim; without one a fresh ULID is generated.  Every tool error of a
  capability call carries the `command_id`.
- **Input refusals.** The capability schema is checked locally with the bounds
  of limit-covered paths removed (`mhs.limits.strip_bound_keywords` over the
  `x-mhs-effective-limits` of `mhs.devices.get`).  A mismatch is `isError:
  true`, text `MHS.CAPABILITY.INPUT_INVALID: <field reasons>`,
  `mhs_error.details.errors`, and nothing is sent.  An out-of-limit value is
  sent, so the endpoint refuses it with an `ENVELOPE_VIOLATION` receipt that
  the evidence keeps (plan 3.5).
- **Protocol.** `SUPPORTED_PROTOCOL_VERSIONS = 2024-11-05, 2025-03-26,
  2025-06-18, 2025-11-25`; an unsupported or missing request gets
  `LATEST_PROTOCOL_VERSION` (2025-11-25).  `resources/read` loads the endpoint
  before routing.  `SERVER_VERSION = _ids.SDK_VERSION`.
- **Discovery.** `_ensure_loaded` also calls `mhs.devices.get` per device (reference
  file, effective limits).  `mhs__devices` is a compact summary (`device_id`,
  `name`, `mode`, `risk_class`, `resources`, `tools`, `hardware_disabled`).
  `mhs__evidence {last_n=10 (<= 50), command_id, include_bundle}` returns
  `{count, head_digest, valid, verify (errors <= 5), receipts, uri}`; the
  full bundle is the resource `mhs://<endpoint>/evidence` (or `bundle` with
  `include_bundle: true`, for hosts without `resources/read`).  New resources:
  `.../evidence` and `.../devices/<path>/reference`.  `mhs__read` resolves a
  unique resource without `device_id`.  `mhs__operations` lists the
  operations of every owned session, reads one (`operation_id`, `wait_ms` <=
  60000) and cancels one.  `mhs__estop` uses an owned session for attribution
  when there is one and never opens or waits for a session.
- **Tool descriptions** (<= 2048 bytes, `TOOL_DESCRIPTION_LIMIT`): title and
  summary, mode and risk, determinism and fidelity gaps (simulators), the
  enforced limits (`ticks 1..10000 (reason)`, allowed sets, per-element
  arrays, `operator_required`), the interlocks whose `required_for` matches,
  the permit requirement, long-running behaviour, the hardware-disabled
  notice, the reference facts (`text [source ref]`) and the not-certified
  notice; over budget, facts are cut first, then interlocks, then limits.
  `annotations`: `readOnlyHint` (read verb: manifest, reference file or
  catalogue), `destructiveHint` (non-read on R2/R3 or hardware/hybrid),
  `idempotentHint` (read/write), `openWorldHint` (hardware/hybrid), `title`.
  `x-mhs` gains `resource` and `verb` and is mirrored in
  `_meta["openmhs/capability"]`.  `MCPProjection(describe_inputs=True)` (what
  `python3 -m mhs.mcp` serves) gives every input property a description with
  type, unit (`Unit: <code>.` or `Unit: none declared.`) and enforced limit;
  the in-process default `False` keeps the authored schema for the G8 gate.
  Control fields and discovery-tool inputs have descriptions (with units).
- **Running receipts.** `accepted`/`running`/`unknown` receipts with an
  operation id get `structuredContent.operation` (`operation_id`, `status`,
  `long_running`, `deadline_ms`, `max_duration_ms`, `unknown_receipt_id`) and
  a text pointing at `mhs__operations`.
- **Priority path.** `serve_stdio` reads on one thread and serves in order on a
  worker; `ping` and `tools/call mhs__estop` (after `initialize`) are answered
  on the reader thread, `notifications/cancelled` on a short-lived thread.  A
  cancellation of a call in flight finds its operation by `command_id` in the
  call's session and sends `mhs.operations.cancel`.  At end of input the queued
  requests finish first; the rest of an oversized line is discarded.
- `--token-file` passes a bearer token to an `--endpoint`.

`MHS/sdk/src/mhs/client.py`:

- `Receipt(dict)` with `status`, `ok`, `pending`, `error`, `code` and
  `raise_for_status()` (raises `MHSRejected` for `rejected`, `failed`,
  `cancelled`, `unknown`).  `invoke`, `write`, `restore`, `estop`, `reset`,
  `cancel`, `get_operation` and `wait` return it.  `invoke(..., check=False,
  wait=False, wait_timeout_s=None)` and `write(..., check=False)`.
- `MHSRejected(MHSError)`: `.receipt`, `.status`; code from the receipt error
  (`MHS.OUTCOME.UNKNOWN` for an `unknown` receipt without one).
- `wait(operation_id, timeout=600)` polls `mhs.operations.get` until
  `completed`, `failed`, `rejected` or `cancelled`; else
  `MHS.OUTCOME.TIMEOUT` with `operation_id` and `may_have_effect`.
- Transport errors: anything urllib raises before the request was sent
  (refused, DNS, unreachable, connect timeout) and a stdio command that does
  not start are `MHS.TRANSPORT.UNAVAILABLE` (retryable, `may_have_effect:
  false`).  A timeout after sending is `MHS.OUTCOME.TIMEOUT`, a lost
  connection after sending `MHS.OUTCOME.UNKNOWN` (stdio: `TRANSPORT.CLOSED`
  for non-effectful methods); both carry `command_id` and `may_have_effect`
  (true for `mhs.command`, `resource.write`, `restore`,
  `safety.estop/reset/permit`, `operations.cancel` and `composition.run`).  `MHSClient.request` adds them for every
  transport.  Legacy codes in the client are replaced by normative ones.
- `client.device(device_id, check=False)` returns a `DeviceHandle` with its own
  session (`open_session(..., make_default=False)`), lazy heartbeat at a third
  of the TTL, `MHS.SESSION.EXPIRED` on a lapse (the next call reopens),
  `invoke/call`, `write`, `read` (primary resource by default), `estop` (no
  session needed), `safety`, `manifest`, `operations`, `cancel`, `wait`,
  `snapshot`, `restore`, `receipts`, `close`, context manager.
- `estop()` needs no session; `export_evidence()` sends only an explicit
  `session_id`; `write()` always sends a `command_id`; `open_session()` drops
  the endpoint-owned `principal.x-meta` members; `CLIENT_INFO` uses
  `_ids.SDK_VERSION`; `_next_id` is thread-safe; `connect()` closes the stdio
  child when `hello` fails.
- SSE: one stream per session (`start_events(session_id=...)`, idempotent per
  session); `subscribe()` starts its session's stream; 400/401/403/404 end the
  stream instead of retrying every 0.5 s.  `close()` shuts the stream socket
  down (`SHUT_RDWR`) and joins the reader: `close()` after a subscription
  takes well under 1 s (was ~15 s).

### Behavioural / compatibility notes

- MCP hosts no longer see `mhs__reset`/`mhs__permit` unless the connector's
  policy sets `operator_tools`; a hidden tool called by name refuses with
  `MHS.AUTH.FORBIDDEN`.  A `session_id` the projection did not open is
  refused.  Receipts of projection calls name the principal
  `agent:mcp/<client>` instead of `mhs-python-client`/`service`.
- `mhs__evidence` returns a summary; the full bundle needs `include_bundle:
  true` or `resources/read`.  `mhs__devices` and the `.../devices` resource
  return the compact summary.
- An input-schema mismatch is a tool result with `isError: true` (was
  JSON-RPC `-32602`).  A limit-covered out-of-range value reaches the
  endpoint and gets a receipt (was refused locally without one).
- `initialize` without a supported version answers `2025-11-25` (was
  `2024-11-05`).  `MCPPolicy.load` treats non-boolean `allow_hardware` values
  as false.
- Client: receipt-returning methods return `Receipt` (a `dict`); a refused
  connection raises `MHS.TRANSPORT.UNAVAILABLE` (was `OUTCOME.TIMEOUT`); an
  e-stop no longer needs `open_session()`.
- Wire methods and tool names are unchanged.

### What changed

`MHS/sdk/src/mhs/cli.py` (rewritten; console scripts `mhs`/`openmhs` and
`python3 -m mhs`):

- **Exit codes** (one table, `exit_code_for`): 0 ok; 1 a receipt that is not
  `completed`/`accepted`/`running`, any endpoint error that is not transport
  or auth, a driver strict mode refuses, an invalid document; 2 usage (argparse
  errors, `--input`/`--patch` not a JSON object, missing files, unsupported
  endpoint form); 3 `MHS.TRANSPORT.*`, `MHS.OUTCOME.TIMEOUT/UNKNOWN`; 4
  `MHS.AUTH.*`, a reset without an interactive operator, a hardware backend
  without `--allow-hardware` (LoadError `hardware_not_allowed`/
  `review_required`); 5 conformance below target; 130 interrupt.  With
  `--json` an error is `{"error": {mhs_code, message, retryable, data,
  remediation}}` on stdout; otherwise one line on stderr.
- **`serve <driver-dir|mhs-adapter.json|conveyor|lab|arm|replay>`**:
  `mhs.adapter.load` (strict) with `--backend fake|sim|hardware` (default
  fake), `--allow-hardware`, `--arm` (operator: `armed=True`; needs
  `--allow-hardware`), `--site-limits`, `--state-dir`, `--endpoint-id`;
  transport `--stdio` | `--port N` (0: free port; default HTTP 7400) |
  `--mcp`; `--host` plus `--token-file` (principal kind `agent`) and
  `--operator-token-file` (kind `operator`), HTTP only; `--mcp-config`,
  `--operator-tools`, `--allow-external-sessions` with `--mcp` only.  `--mcp`
  serves `MCPProjection(describe_inputs=True)` over an in-process client.
  Reference names keep `mhs.reference.serve` (`--test-profile`, `--noise`,
  `--seed`, `--bundle`); driver-only flags on them are usage errors.  SIGTERM
  unwinds like Ctrl-C (state dir and drivers closed; the previous handler is
  restored).  A non-loopback bind without a token exits 4
  (`MHS.AUTH.TRANSPORT_INSECURE`).
- **`driver ...`** delegates to `mhs.driver.__main__.main` (same as
  `python3 -m mhs.driver`).
- **`validate <dir|file>`**: driver directory (strict findings of the
  declared, fake and sim views; `driver.lock.json` schema, with the G2
  tolerance for synthetic tutorials; stale `reference.json`/`REFERENCE.md`;
  `site-limits*.json`) or a JSON document against its schema (from `--schema`,
  `$schema`, the file name or its keys; plus strict device resolution for an
  `mhs-adapter.json`, `validate_report` for a conformance report,
  `verify_bundle` for an evidence bundle).
- **`describe`** (alias **`inspect`**): per device mode, risk, models, trust
  (not certified, conformance claims), e-stop, safe state, interlocks, verb,
  resource and effective limits per capability, fidelity gaps, facts.
- **`devices`**: one line per device (`--json` keeps the full manifests).
- **`read`**, new **`write <resource> --patch`**, **`call`** (`--permit-id`,
  `--wait`), **`session`** (the session now outlives the command; pass it as
  `--session-id`): `--mode` defaults to the device's own mode (was
  `simulated`); `--device` takes a unique id segment.
- **`estop [REASON]`**: no session, no mode; every device unless `--device`;
  exit 0 only when every receipt is completed.  **`status`**: one line per
  device.  **`reset`**: `--operator-token-file` (required), HTTP only, stdin
  must be a TTY (else exit 4, nothing sent), shows the latch and interlocks and
  asks the operator to type `reset`.  `safety` is kept as a deprecated
  spelling.
- **`evidence --ledger FILE`**: verifies a code-file ledger against the
  exported bundle (`mhs.run.verify_ledger`).
- **`run [--ledger-dir D] script.py [args]`**, **`discover`** (below).
- **`conform`**: subject is a driver directory (in process, fake or sim
  backend), `-e`, `--command` or `--reference`; prints
  `conformance_summary` (failing and capping test ids); `--out/-o/--output`,
  `--require-level`, `--allow-actuation`, `--read-only`, `--fixtures`; exit 5

- **`version`** prints SDK, spec and protocol versions; the parser
  description is `_ids.PROJECT_NAME` plus the non-affiliation notice.

`MHS/sdk/src/mhs/run.py` (new): `lab(*targets, check=True, ledger=True,
mode=None, ttl_s=600, token=None, principal=None)` returns a `Lab` of

### What changed

- **Major: `mhs estop` stops every device it can** (`_cmd_estop`).  It lists
  the devices once and resolves every `--device` name before sending
  anything.  An unknown or ambiguous short name is reported as an error
  (`MHS.DEVICE.UNKNOWN` / `MHS.HOST.DEVICE_AMBIGUOUS`) and is never guessed.
  An `mhs.safety.estop` is then sent to every resolved device, and an
  `MHSError` is caught per device.  The output has one receipt line per
  device, one stderr line per failure and a final `NOT stopped: ...` line.
  `--json` prints `{"receipts": [...], "errors": [{"device", "error"}]}`.
  The command exits 0 only when every requested device has a `completed`
  receipt.  Otherwise it exits with the code all its failures share (3 when
  only transport failed, 4 when only authorisation did), else 1.  Before the
  fix, a mistyped `--device` aborted the loop, so the devices named after it
  were never stopped.
- **`Lab.estop()`** (`run.py`) tries every device before raising.  The first
  error is raised again with `data["errors"]` (`{device_id, mhs_code,
  message}` per device) and `data["receipts"]`.  A refused stop is still
  returned as its receipt.
- **Exit-code precedence** (minor, `cli.md` row 4).  `_receipt_exit` and
  `exit_code_for(MHSRejected)` map a refusal whose `error.mhs_code` is
  `MHS.AUTH.*` to 4.  This matches TPT-052 "4 authentication error" and the
  documented row.  Examples: a hardware reset sent with the client token
  (`MHS.AUTH.FORBIDDEN`) and `MHS.AUTH.HARDWARE_DISABLED`.  Every other
  receipt gives 0 or 1 by its status; for example, a receipt with status
  `unknown` gives 1.  `mhs run` uses the same mapping.  The precedence is now
  stated in the module docstring, in the `--help` epilog and in `cli.md`.
- **`mhs conform --json`** (minor) keeps stdout a single JSON document.  The
  "below target" and "report saved" lines go to stderr when `--json` is
  given.
- **`verify_ledger`** (minor) returns `reasons`.  It is no longer valid with
  `checked: 0` in two cases: the bundle's endpoint is not among the ledger's
  `endpoints` (`endpoint_not_in_ledger`), or the ledger has final receipts
  but none of them from this endpoint (`no_receipts_for_endpoint`).  The
  other reasons are `chain_invalid`, `missing_receipts` and
  `mismatched_receipts`.  `mhs evidence --ledger` against the wrong endpoint
  now prints `valid: false` and exits 1.
- **Discovery docstring** (minor).  The comma form `stdio:python3,-m,...` is
  documented for `parse_target` only, that is `-e` and `targets=`.
  `MHS_ENDPOINTS` is split at commas first, so its stdio entries separate
  their words with spaces.  `cli.md` says the same.
- **`mhs serve replay`** without `--bundle`, or with a `--bundle` that is not
  a file, is a usage error (exit 2).  It used to exit 1 through
  `SystemExit` from `mhs.reference`.
- **Ledger location** (minor).  `Ledger` resolves its directory to an
  absolute path when it is created, so a script's `os.chdir()` no longer
  moves the ledger.  `run_script` restores the working directory after the
  script.  `mhs run` prints the ledger path relative to the caller's
  directory when it lies inside it, and the absolute path otherwise.
- **`lab(token=...)`** (minor).  The token is sent only to endpoints named
  in the call: an endpoint string, an in-process server, or the `host:port`
  of an `mhs://` device id that discovery does not list.  A discovered
  endpoint gets only the `token_file` of its own endpoints-file entry.  A
  device listed by two discovered endpoints raises
  `MHS.HOST.DEVICE_AMBIGUOUS` with `data["endpoints"]`; the first claim no
  longer wins silently.  A device name that an endpoint named in the same
  call already serves is not looked up through discovery.
- `_pick_device` (`read`/`write`/`call`/`describe`/`reset`) reports an
  ambiguous short `--device` name locally as `MHS.HOST.DEVICE_AMBIGUOUS`.
  Before, the name was passed through and the endpoint answered
  `MHS.DEVICE.UNKNOWN`.  The exit code is 1 either way.

## MERGE-C2 fix — `allow_hardware` parsed by truthiness in the host config (verifier major)

The MERGE-C2 verification found a safety-relevant bug that was not in the open-issue list. It predates the
merge (baseline `config.py:135`).

- Repro (`scratch/verify-MERGE-C2/allow_hardware_string.py`): with `{"enabled": true, "allow_hardware": "false"}`,
  `MHSConfig.load` gave `allow_hardware=True` (`bool("false")`), so `MHSHost._hardware_gate` opened sessions on
  `mode: hardware` devices. That affects the integration CLI `call`/`read` and the developer-overlay tools.
  `mhs.mcp.MCPPolicy.load` reads the same document strictly and kept the gate shut, so the two parsers
  disagreed.
- Fix (`integration/openai4s/openai4s_mhs/config.py`):
  - `_read_flag(raw, key)` returns `raw.get(key, False) is True`. `allow_hardware` and `enabled` both use it,
    the rule `MCPPolicy.load` applies.
  - A policy flag (`enabled`, `allow_hardware`, `operator_tools`, `allow_external_sessions`) that is present but
    not a JSON boolean is listed in the new `MHSConfig.notices`. `to_settings()`, and so `python3 -m openai4s_mhs
    status`, shows it under `notices`. Notices block nothing, because every such value reads as false.
    `warnings`, which block agent rows, are unchanged.
  - A settings document that is not a JSON object raises `ValueError`, as `MCPPolicy.load` does. It used to
    fail later with an `AttributeError`.
- Docs: the `config.py` module docstring and README §3 state the rule ("Only a JSON `true` turns `enabled` or
  `allow_hardware` on ... `status` lists it under `notices`").
- Tests (`integration/openai4s/tests/test_config.py`):
  - `test_only_a_json_true_allows_hardware`: `"false"`, `"true"`, `1`, `"1"`, `"yes"`, `[true]` and `{"on": true}`
    all load `False`. `MCPPolicy.load` agrees on each value, a notice is reported, there is no warning, and
    `MHSHost._hardware_gate` refuses with `MHS.HOST.HARDWARE_GATED`. A JSON `true` opens the gate.
  - `test_settings_document_must_be_an_object`.
  - The mutant with `bool(raw.get("allow_hardware", False))` fails 7 subtests. After the fix the repro prints
    `MHSConfig.allow_hardware: False`, `MCPPolicy.allow_hardware: False` and `MHSHost hardware gate: refused`.

Behavioural change: a quoted or numeric `allow_hardware` no longer enables hardware in the OpenAI4S host. That
was never the documented behaviour (README §8: "refused unless allow_hardware=true").
