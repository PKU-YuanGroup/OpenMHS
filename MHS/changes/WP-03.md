Findings addressed (library half; the server and bridges adopt these modules in
WP-04/WP-05): SPEC-02, SC-03, SDK-03, DRV-02, FIT-03, FIT-ROS-01, SIM-01 (limit
grammar, array/nested/per-element enforcement, typo-proof rules, intersection

catalogue becomes binding: class verb, risk floor, permit, limits, kinds and a

## What changed

Five new pure modules under `MHS/sdk/src/mhs/` (stdlib only, Python 3.10+, no
import of `mhs.server` or `mhs.bridge`), plus tests. No existing file was
edited.

### `mhs/signals.py`
- `Cancelled`, `DriverFailed(code, message="", native_code=None)`, `Busy`,
  `OutcomeUnknown`, all subclasses of `DriverSignal(Exception)`.
- `outcome(exc)` classifies any exception: Cancelled (and asyncio /
  concurrent.futures `CancelledError`) -> `cancelled`, no code; DriverFailed ->
  `failed` with its code; Busy -> `rejected` + `MHS.DEVICE.BUSY` (retryable,
  optional `retry_after_ms`); OutcomeUnknown -> `unknown` +
  `MHS.OUTCOME.UNKNOWN` (not retryable); anything else -> `failed` +
  `MHS.ADAPTER.SHIM_FAILED` with a redacted message (exception type only).
- `DriverFailed` accepts any registered normative code (legacy aliases are
  normalised; an unregistered code raises `ValueError`) and exposes
  `driver_subset` so a strict loader can refuse codes outside
  `mhs.errors.DRIVER_SUBSET`. `native_code` is kept verbatim in `details()`.

### `mhs/units.py`
- UCUM parser over atoms + metric prefixes: products `.`, quotients `/`
  (left-associative, as UCUM requires), leading `/` (`/min`), parentheses,
  integer exponents (`m/s2`, `s-1`), `{annotations}`, integer factors.
  Dimensions are vectors over m, kg, s, A, K, mol, cd, rad (angle is a base
  dimension, so rad never converts to a ratio). Factors are exact fractions,
  so `convert(1, "m/s", "mm/s") == 1000` and `convert(50, "%", "1") == 0.5`.
- Every unit of the bridge table still parses and converts identically, except
  `%`, which is now a ratio of 0.01 (the bridge treated it as 1). Added `mW`,
  `Ohm`, `kOhm`, `nA`, `uV`, `GHz`, `Torr`, `atm`, `mm[Hg]`, `[psi]`, `[degF]`,
  `[g]`, `[ppm]`, `[ppb]`, `J`, `W`, `C`, `S`, `F`, `T`, `mol`, `cd`, `d` and every
  prefixed metric form (`mL/min`, `uL/h`, `uL/s`, `K/min`, `rad/s`, `N.m` ...).
- `convert(value, src, dst, factor=None, *, offset=None, delta=False)`: an
  explicit factor/offset must equal the derived one (relative tolerance 1e-9)
  or `UnitError` is raised; temperature offsets apply only between single
  absolute temperature atoms (K, Cel, [degF], prefixed K) and never with
  `delta=True` (`field_is_delta(schema)` reads `x-mhs-delta`).
  `UnknownUnitError(UnitError)` distinguishes unparseable codes.
  `convert_unit(value, from, to)` is the bridge-compatible spelling.

### `mhs/limits.py`
- `parse_path` / `format_path`: the strict `limitPath` grammar (`field`, `a.b`,
  `a[*]`, `a[N]`), producing the same tokens as `mhs.bridge.base.get_path`.
- `LimitRule`: the closed rule `{min, max, allowed, unit, reason, source, ref,
  names, per}` validated on construction (unknown member -> `unknown-rule-member`;
  vendor_doc/upstream_code need `ref`; per-element lists of equal length;
  `min <= max`; `per` needs a scalar `max`).
- `compile_limits(input_schema, sources, narrow_only_sources=())` ->
  `EffectiveLimits`. Sources are `LimitSource(label, limits, narrow_only,
  partial, default_source)` objects, `(label, map)` pairs or a mapping. Paths
  resolve through properties, items/prefixItems, local `$ref` and `allOf`.
  `LimitConfigError(ValueError)` carries `rule`, `path`, `source`, `member`
  and is raised for: grammar errors, unresolvable paths
  (`limit-path-resolves`), unknown members, min/max on non-numeric fields and
  `allowed` of the wrong type (`limit-type`), per-element bounds on scalars,
  element paths, variable-length or nested arrays and wrong lengths
  (`array-bound-length`), a unit other than the field's `x-mhs-unit` or units
  that disagree (`limit-unit-matches-field`), names that disagree
  (`names-agree`), sources that leave no valid value (`empty-range`), an
  overlay that widens anything, element by element (`overlay-narrows`), and an
  overlay that is itself `operator_required` (`overlay-supplies-bounds`).
- Intersection: max = min of maxima, min = max of minima (per element when any
  source is per-element), allowed = intersection (JSON equality), names must
  agree; every bound keeps its `Origin(label, source, ref, reason)`. A trailing
  `[*]` on an array is the same rule as the bare array path. `per` rules are
  collected separately as `CumulativeRule`s (budgets, not per-call bounds).
  `operator_required` paths are reported in `EffectiveLimits.unset` until a
  narrow-only source supplies a bound. Overlay narrowing is listed in
  `EffectiveLimits.narrowed` (`setpoint.max: 150 -> 95`).
- `check(payload, effective)` -> every `Violation(path, kind, bound, value, unit,
  source, element_name, limit_path, reason, provenance, ref)`; `to_details()`
  is the `MHS.SAFETY.ENVELOPE_VIOLATION` details. It evaluates each array
  element and nested leaf, skips absent optional fields, evaluates schema
  defaults of omitted fields, and never lets a string, boolean, NaN, infinity
  or wrong shape pass a numeric bound (`kind: type`); elements beyond a
  per-element bound list are `kind: length`.
- Two-pass support for the server: `bound_keyword_paths(effective)` (schema
  pointers of limited fields) and `strip_bound_keywords(effective)` (copy
  without minimum/maximum/exclusive* and, where `allowed` is set, enum/const).
  `numeric_leaf_paths` / `unlimited_numeric_leaves` support the
  `LIMITS_UNSET` rule. `envelope_sources`, `overlay_sources` and
  `pattern_matches` turn manifest envelopes and `site-limits.json` into sources.

### `mhs/catalog.py`
- Loads `capabilities.json`: `$MHS_SCHEMA_DIR` (the file itself, `spec/` below
  it, or `spec/` next to the schema directory), then the packaged
  `mhs/_data/spec/capabilities.json` (a checkout with a different copy wins,
  with a one-time `RuntimeWarning`), then the checkout's `MHS/spec`.
  `default_catalog()` reloads when the file changes; `clear_default_catalog()`.
- `Catalog.get / ids / search / kind_ok / class_digest`, module-level `get`,
  `search`, `is_extension` (`x-cap.*`, `cap.x.*`), `schema_digest` (sha256 of
  JCS, `sha256:<hex>`), `extension_digest(input, output)` (the CAP-037 digest of
  an inline extension binding), `risk_at_least`.
- `resolve_binding(cap_id, binding_input_schema, binding_output_schema,
  resource_kind, device_mode, *, state_schema, binding_limits, binding_verb,
  binding_requires_permit)` -> `Effective {verb, input_schema, output_schema,
  risk_floor, requires_permit, class_limits, kind_ok, mode_ok, drift, status,
  extension, inherited_input/output, class_input/output_schema, class_digest,
  constraints}`. Unknown `cap.*` ids raise `UnknownCapabilityError`; a missing
  or skeleton binding schema inherits the class schema; any other binding
  schema is merged with the class schema into one schema, binding ∩ class
  (`merge_schema`, see "Verification fix round" below);
  `cap.device.configure.v1` derives its input from the writable state
  properties (and its `applied` output from the same set) and needs
  `state_schema`; `resource_kinds: ["*"]` and `see_also` synonyms are kind_ok.
- Drift (`Drift(kind, path, message)`): `property-not-in-class` (closed
  class), `type-differs` (integer for number is a narrowing), `unit-differs`,
  `enum-not-subset`, `required-missing` (a stated required list that is not a
  superset), `widens` (an explicitly wider bound keyword or an explicitly open
  `additionalProperties` on a closed class), `verb-differs`, `limit-widens`.
  Keywords a binding omits are inherited into the effective schema and are
  not drift; nested objects, items, prefixItems and output schemas are
  compared too.
- `compile_manifest_limits(manifest, overlay=None)` -> `ManifestLimits` (one
  `BindingLimits(capability_id, resource, effective, limits)` per binding):
  class limits (partial, provenance `class_default`) ∩ binding limits (strict) ∩
  envelope (exact id strict, pattern partial but each path must resolve in some
  matching binding) ∩ overlay (narrow-only, provenance `operator`; capability
  entries must name a bound capability and parameter entries a writable
  parameter). Envelope entries for unbound capabilities are returned in
  `unused_envelope`; `narrowed` and `unset` summarise the device.

### `mhs/reference_file.py`
- `render(manifest, effective_limits_by_capability=None, overlay=None, facts=(),
  tags=(), provenance=None, *, catalog=None, upstream=None)` returns a dict that
  validates against `reference.schema.json` (checked before returning;
  `ReferenceFileError` otherwise). Limits default to
  `compile_manifest_limits(manifest, overlay)`; a `ManifestLimits` or a
  `{cap id | (cap id, resource): EffectiveLimits}` mapping may be passed.
  Measures = non-adjustable state properties plus read bindings that need no
  input (nothing required or limited, no permit, risk R0), typed after their
  first required output field with a unit;
  adjusts = writable state of resources bound to `cap.device.configure.v1`
  (limit or `operator_required`); actions = every other binding with
  flattened input/output field descriptors (`a.b`, `a[*].b`) carrying
  effective limits and element names; action names come from the binding
  member `x-mhs-name` or the capability id. Risks never fall below the class
  floor or the device risk class. Safety copies e-stop, safe state,
  interlocks, watchdog, lists unset operator_required limits and states
  `not_certified: true`; `estop.native` comes from `render(...,
  estop_native=)` or the manifest's `safety.estop.native`. Overlay
  digest/narrowed and provenance (generator, SDK version, catalogue and
  manifest digests, plus caller-supplied authored_by/reviewed_by only) are
  recorded.
- `dump(ref)` -> JCS bytes (byte-deterministic); `validate(ref)`;
  `render_markdown(ref)` -> deterministic `REFERENCE.md` with the sections
  Measures, Adjusts, Actions, Safety, Facts.

override narrower ones, typos and unresolvable limit paths fail at load, and
array/nested limits are enforced.

## Compatibility notes
- `mhs.units` is a superset of the bridge table except `%`; the bridge keeps its
  own table until WP-05 switches to `mhs.units`.
- `LimitRule` is closed: the legacy cumulative key `limit` (read by
  `server._check_limits` as a fallback for `max`) is not a rule member.
- `units.convert` raises `UnknownUnitError` for codes outside the table even
  with an explicit factor; the bridge's ADPT-021 fallback for custom codes must
  catch it explicitly if it is kept.
- A blanket scalar overlay bound that is wider than any per-element bound is
  refused (it would widen that element), matching the WP-02 reference checker.
- When the bounds of one effective rule come from different sources, the
  reference file's single `source`/`ref`/`reason` are those of the `max`
  bound (then `min`, then `allowed`); per-bound origins stay available on
  `EffectiveRule` and in every `Violation`.

## Deviations
- `units.py` expresses the table as atoms plus metric prefixes instead of a
  literal copy of the bridge's flat table (every bridge entry is covered and
  tested).
- `Violation` names the failed check `kind` (`min`/`max`/`allowed`/`type`/
  `length`) and carries the limit value in `bound`, plus `limit_path`, `reason`
  and provenance, in addition to the specified fields.
- `render`'s `effective_limits_by_capability` is optional (compiled from the
  manifest and overlay when omitted), and `compile_manifest_limits` was added
  to `catalog.py` so the renderer and the server share one composition of
  class, binding, envelope and overlay limits.

## Verification fix round

An independent verification failed the first round on one major and five
minor issues; all are fixed inside the WP-03 files.

- **major, `catalog.resolve_binding` (SC-01 fix 3, SPEC-05).** The drift rules
  treated keywords a binding omits as inherited, but `Effective.input_schema`
  / `output_schema` were the bare binding schema, so a binding could drop a
  class `required`, unit, bound, enum or the closed `additionalProperties`
  with no drift. New `catalog.merge_schema(binding, class)` builds binding ∩
  class as one merged schema (no `allOf` around the properties, so
  `limits._Resolver` and `reference_file._walk_fields` still see one
  `properties` map): the class's `type`, `x-mhs-unit`, `x-mhs-delta`,
  `x-mhs-open`, `enum`/`const`, `uniqueItems`, min/max/exclusive*/
  minItems/maxItems/minLength/maxLength/minProperties/maxProperties,
  `required` and `additionalProperties` are copied wherever the binding omits
  them, recursively through `properties`, `items` and `prefixItems`; class
  properties an open binding does not list are added with their class schema
  (a closed binding keeps its narrower set, but class-required properties are
  still added); a `pattern`/`format`/`multipleOf` that both state differently
  is kept twice (the class's under `allOf`) so both apply. Keywords the
  binding states keep the binding's value: a conflict is drift (strict
  refuses it; compatibility mode runs the binding's version, the class schema
  stays in `class_input_schema`). Repro of the verifier (setpoint binding
  `{target_temperature: number, rate: number}`): no drift, and the effective
  schema now rejects `{}`, `rate: -5` and extra properties; the rendered
  reference publishes `target_temperature` as `required: true`, unit `Cel`.
  Drift additions: an array-level `x-mhs-unit` against the class item unit,
  `prefixItems` elements against the class `items`, an `enum` against a class
  `const`, and a closed binding schema that leaves out a class-required
  property (`required-missing`). The pinned 9 + 1 reference drift sets are
  unchanged. New invariant tests: for every class a bare binding (every
  property listed without keywords) has no drift and its effective schema
  states every class constraint; the same holds for every non-drifting
  binding of the reference endpoints and valid examples (and, checked in
  scratch, for all 9,109 registry bindings; all 1,967 registry manifests still
  compile and render).
- **minor, `limits` related keys.** A narrow-only rule is now also compared
  with the rules of the same array under another key: `a` bounds every
  `a[N]`, `a[N]` bounds element N of `a`, `a[*].b` meets `a[N].b`, for
  `min`/`max` (per element) and `allowed`. A wider overlay raises
  `overlay-narrows`; a narrower one is logged against the real bound
  (`jp[2].max: 0.5 -> 0.25`, not `unbounded`).
- **minor, overflow.** `limits._is_number` treats an integer beyond the double
  range as not a finite number (no `OverflowError`): `check` returns a `type`
  violation, `LimitRule.parse({"max": 10**400})` raises `LimitConfigError`;
  `Violation.to_details()` carries integers beyond 2**53-1 as decimal strings
  (JCS-safe). `units.convert` raises `UnitError` for such values, for declared
  factors/offsets beyond the double range and for results that overflow.
- **minor, `units._check_declared`.** The factor check is purely relative
  (`rel_tol=1e-9`, `abs_tol=0`), so `convert(1, "fL", "L", factor=0)` is
  refused; an absolute slack of 1e-12 remains only for a derived offset of
  exactly 0.
- **minor, `reference_file` measures and e-stop.** (a) A read binding that
  needs no input (no required input, no limit rule, no permit, risk R0) is a
  measure with `cap_id`, typed after its first required output field with a
  unit (`cap.measure.temperature.v1` -> number, `Cel`, matching the WP-02
  example's `measure_temperature`); reads that need input stay actions.
  (b) `render(..., estop_native=...)` (or the manifest's
  `safety.estop.native`) emits `safety.estop.native` (a name, or `null` for a
  software-only stop); `REFERENCE.md` states it.
- **minor, `reference_file` provenance and partial limits.** `provenance` may
  only add `authored_by`/`reviewed_by` (`PROVENANCE_KEYS`); anything else
  raises `ReferenceFileError`, so the generator, SDK version and digests can
  never be overwritten. Bindings missing from a partial
  `effective_limits_by_capability` mapping are compiled with
  `compile_manifest_limits(manifest, overlay)`, so the recorded overlay
  applies to them and their narrowed lines appear.

### Leftover minors fixed (reviewer repros of verify-WP-03/r2 ported first as failing tests)
- **limits, overlay order** (`probe1.py` 1): a narrow-only rule was compared
  with the current state, including earlier overlay rules, so `{"a[2]": 0.25,
  "a": 0.3}` was refused while the reverse order was accepted. Regular sources
  are now applied first and every narrow-only rule (min/max, `allowed`,
  cumulative `per` budgets, same key or a related key of the same array) is
  judged against what the regular sources alone allow; narrow-only rules
  intersect among themselves. Order never changes the result, a rule wider
  than the regular sources is still refused in any order, and each `narrowed`
  line is relative to the regular sources (`a[2].max: 0.5 -> 0.25` in both
  orders; duplicates are dropped).
- **units overflow** (`probe1.py`/`probe2.py` 2): `conversion()` and an
  explicit `factor=` raised `OverflowError` for factors beyond the double
  range (`Ym20 -> m20`); they raise `UnitError`, as does a non-zero factor that
  rounds to 0.0. `convert(0, ...)` stays exact.
- **canonical JSON** (`probe1.py` 3): `Violation.to_details()` now passes the
  bound through the same conversion as the value, recursively (integers
  beyond 2**53-1 and non-finite floats become strings), so details are always
  `canonical.jcs`-safe. `LimitRule` also refuses integer bounds and `allowed`
  values beyond +-(2**53-1) at load time (`limit-rule-invalid`): a reference
  file could not carry them (no registry manifest has one).
- **drift through combinators** (`probe1.py` 7/8): `_schema_drift` compares
  every local `$ref` target and `allOf` branch (recursively, cycle-safe) with
  the class like the node itself (type, unit, enum/const, bounds, open
  `additionalProperties`, properties, items). `required` is the exception: a
  branch only adds required properties (the class's are inherited at the top
  of the merged schema), so `required-missing` is reported only when the node
  states `required` and, together with its branches, leaves a class-required
  property out. Duplicate drift entries are collapsed.
- **measures keep their inputs** (`probe2.py`): a read binding rendered as a
  measure lists its optional parameters as `inputs` (field descriptors,
  `required: false`); all 12 catalogue read classes with optional inputs keep
  them. `REFERENCE.md` measures gain an "Optional inputs" column. (Requires the
