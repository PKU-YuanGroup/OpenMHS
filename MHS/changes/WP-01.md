# WP-01 — Identity, licensing, packaging and site rebrand

Findings addressed: AF-01, OSS-01, OSS-02, OSS-03, OSS-10, OSS-12 (security
policy and code of conduct), OSS-14 (version line, build debris ignores),
SC-07 (namespace part), SC-09, SDK-05 (store part), SDK-13 (packaging part),
SPEC-13 (SDK/site part), TESTS-07 (site freshness and capability-id gate),
MISSED: "installed wheel drops conformance JSON", "CC BY grant purports to
cover Anthropic quotations", "site build silently substitutes a synthetic
registry".

## What changed

### Identifiers in one module
- New `MHS/sdk/src/mhs/_ids.py`: `PROJECT_NAME="OpenMHS"`, `DIST_NAME="openmhs"`,
  `SPEC_VERSION="0.9"`, `SDK_VERSION="0.9.0.dev0"`, `WIRE_VERSION="1.0"` (wire
  revision 1, unchanged), `SCHEMA_BASE="https://mhs.openai4s.org/schema/0.9/"`
  (placeholder on the reserved `.invalid` TLD), `LEGACY_SCHEMA_PREFIX` (read-only,
  remove in 0.10), `REGISTRY_ID="openmhs-registry"`, `ADAPTER_ID_PREFIX="openmhs:"`,
  `NON_AFFILIATION` (one sentence). This is the only file under `MHS/sdk/src`
  that spells the legacy domain.
- `mhs.__version__` now comes from `_ids.SDK_VERSION` (was `"1.0.0"`); all
  existing exports kept. The package docstring states non-affiliation.

### Packaging
- `MHS/sdk/pyproject.toml`: distribution `openmhs` 0.9.0.dev0, SPDX
  `license = "Apache-2.0"` with `license-files = ["LICENSE", "NOTICE"]`
  (`setuptools>=77`), `Development Status :: 3 - Alpha`, description with the
  non-affiliation phrase, console scripts `mhs` and `openmhs` -> `mhs.cli:main`,
  frozen package data `["_data/**/*", "conformance/*.json", "driver/templates/**/*"]`.
  The no-op `[tool.unittest]` table was dropped.
- `MHS/sdk/LICENSE` and `MHS/sdk/NOTICE` are byte-identical copies of the root
  files; `MHS/sdk/MANIFEST.in` for sdists; `MHS/sdk/.gitignore` ignores
  `src/mhs/_data/`, `build/`, `dist/`, `*.egg-info/`.
- New `MHS/sdk/tools/sync_data.py`: mirrors `MHS/schema/*.json`,
  `MHS/spec/capabilities.json` and `MHS/spec/errors.json` into
  `src/mhs/_data/{schema,spec}/` (removing stale files); `--check` exits 1 on any
  drift (missing, extra or differing file) and 2 on unreadable/invalid sources.
  Both modes check that every schema `$id` starts with `SCHEMA_BASE`; the check
  is advisory while every schema still uses the legacy prefix and becomes an
  error automatically once any schema adopts `SCHEMA_BASE` (WP-02), or now with
  `--strict-ids`.
- Verified: the wheel contains 13 schemas, `capabilities.json`, `errors.json`,
  `conformance/applicability.json` and `traceability.json` plus both licence
  files; in a fresh venv outside the repo `python -I -m mhs.conformance --help`
  exits 0, `default_store()` validates the conveyor example, and a stdio
  conformance run reaches CL2.

### Schema store (`mhs/schema/store.py`)
- Lookup order: `$MHS_SCHEMA_DIR`, an explicit `start` argument, the packaged
  `mhs/_data/schema` (via `importlib.resources`), then the existing repository
  walk and working directory.
- `$id`s under `SCHEMA_BASE` and `LEGACY_SCHEMA_PREFIX` resolve to the same
  document (in `load`, `resolve` and `$ref` resolution), whichever prefix the
  file declares.
- New `SchemaStore.resolve_public(ref)` and `public_schema_name(ref)`: only a
  bare lowercase `[a-z0-9-]` name ending in `.schema.json`/`.json`, or a full id
  under a known prefix; slash, backslash, `..`, `~`, `:`/drive letters,
  absolute paths, other hosts and over-long refs raise `SchemaError`; only
  direct children of the store roots are returned (never a file loaded by a
  developer elsewhere).
- New developer-only `SchemaStore.load_path(path)`. `SchemaStore.load(key)` no
  longer follows arbitrary filesystem paths or `~`: it consults the index and
  files inside the store roots only.
- Validator semantics are unchanged: `validate(x, "/path/schema.json")`,
  `validate_file`, `Validator().validate(x, path)` and `store.validate(x, path)`
  still accept a local schema path (routed through `load_path`).
- New helpers exported from `mhs.schema`: `KNOWN_SCHEMA_PREFIXES`,
  `packaged_data_dir()`, `public_schema_name()`.
- Clearer error when no schema directory exists at all.

### READMEs

### Site (`MHS/site/**`)
- `deploy/CNAME` deleted; the build never writes a CNAME.
- Site URL is a build parameter: `--site-url` or `$OPENMHS_SITE_URL`, no
  default host. Without it there are no canonical links, no `og:url`, no
  BreadcrumbList URLs and no `sitemap.xml`; `robots.txt` gets a `Sitemap:` line
  only with a URL.
- `--out DIR` builds anywhere; a non-empty directory is replaced only when it
  is the default `_site/` or carries the new `.openmhs-site` marker; source
  directories and their ancestors are refused.
- `--release` fails instead of using the synthetic registry fallback when
  `MHS/registry/index.json` is missing or empty.
- Identity: title/brand `OpenMHS` (from `_ids`), no Organization JSON-LD,
  `og:site_name` `OpenMHS`, author "The OpenMHS Authors", no `editors@`
  mailbox, no "MHS Editors" footer; the non-affiliation banner opens every page
  and is repeated in the footer; prose that named this project "MHS" or
  "MHS-1.0" now says "OpenMHS"/"OpenMHS 0.9" (mentions of Anthropic's MHS are
  attributed). "How Anthropic MHS works" left the primary/mobile navigation and
  became the secondary page "Relation to Anthropic's MHS preview" (footer and
  banner link); its link to Anthropic's landing domain was replaced by a
  pointer to appendix D. Download bundles are `openmhs-0.9-*.zip` and ship
  `LICENSE`/`LICENSE-docs`/`NOTICE`.
- `download/download-manifest.json` now records `inputs`: the workspace path
  and SHA-256 of every source file bundled into the downloads (plus project,
  non-affiliation, spec and wire versions).
- `check.py`: `--site`, `--site-url`, `--capabilities`, `--fresh`, `--verbose`.
  New failures: an `Organization` JSON-LD node; a page without the
  non-affiliation sentence; canonical/sitemap URLs outside the site URL (or any
  canonical/sitemap when built without one); a capability id outside
  `MHS/spec/capabilities.json` (`cap.internal.*`/`cap.x.*` reserved; spec prose
  pages exempt); a download manifest without input digests, or a bundle member
  that is not a recorded input. Inputs that differ from the current checkout
  are a warning, or an error with `--fresh`.
- `serve.py --site DIR`; `deploy/README.md` and the Pages workflow template
  rewritten for a user-owned domain or GitHub Pages.
- Playground receipts for e-stop/reset use `cap.internal.safety_estop.v1` /
  `cap.internal.safety_reset.v1` (as the spec and server do) instead of the
  non-catalogue `cap.device.estop.v1`/`cap.device.reset.v1`; the home-page
  example `cap.motion.move_to.v1` became the catalogue class
  `cap.motion.joint_position.v1`.
- Two f-strings that only parsed on Python 3.12+ were rewritten; the generator
  now builds byte-identically on Python 3.9 and 3.14.
- `MHS/site/_site` was regenerated with the default build (no site URL) so the
  frozen artifact satisfies the new `check.py`.

## Behavioural changes
- `mhs.__version__` is `0.9.0.dev0`; `mhs version` prints it.
- `SchemaStore.load()` refuses absolute paths, `~` and paths that leave the
  store roots. This already closes the arbitrary-file read through
  `mhs.schema.get` / `GET /mhs/v1/schema/<ref>` (SDK-05), even before WP-04
  switches those routes to `resolve_public`.
- With `src/mhs/_data` present, the default store reads the packaged copies.
  In a source checkout whose `MHS/schema` changed after the last sync, the
  store uses the checkout and warns once (`RuntimeWarning`) instead of serving
  stale schemas.
- A default site build has no canonical URL and no sitemap.

## Compatibility notes
- Wire identifiers are unchanged (`mhs.*`, `MHS.*`, `mhs_version: "1.0"`), as
  is the import name `mhs`.
- Documents with legacy `$schema`/`$id` URLs keep validating through the store
  during 0.9.
- `find_schema_dir()`/`mhs_schema_dir()`/`SchemaStore(...)` signatures are
  unchanged; only the search order gained the packaged directory.

## Deviations
- The packaged `_data` is skipped (with a warning) when the package runs from a
  checkout whose `MHS/schema` differs from it; otherwise the specified order
  holds. Rationale: other work packages edit `MHS/schema` and would otherwise
  test against stale copies.
- `check.py` exempts rendered specification prose (`spec/*.html`) from the
  capability-id check, because the spec cites forbidden/hypothetical ids as
  examples (`cap.motion.move.v1`, `cap.fluid.aspirate.v2`), and treats
  `cap.internal.*` and `cap.x.*` as reserved namespaces.
- The licence texts were taken from canonical copies already present in the
  read-only corpus (Apache-2.0 matching the well-known apache.org digest; the
  CC BY 4.0 legal code identical in two independent upstream copies) rather
  than typed from memory.
