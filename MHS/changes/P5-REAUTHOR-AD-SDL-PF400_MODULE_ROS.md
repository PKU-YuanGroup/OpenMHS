## What the package does

Device `pf400`, kind `robot.arm`, mode `hardware`, risk R2 (above the card floor R1). The clone README names a "PF400 Collaborative Robot Arm" (`README.md:2`) and does not name a manufacturer in that line. Vendor and model follow that wording.

`x-cap.ad-sdl.move_joints.v1` sends `mspeed` and then `MoveJ` on robot port 10100, as two receives. `Class_command.gpl:280` sets the default reply to 0. The client says a leading 0 means the command was successful (`tcp_driver.py:23`). That token is not a reached flag. The output repeats the profile, the joint numbers and the speed that were sent.

`x-cap.ad-sdl.halt.v1` and the e-stop open status port 10000 themselves, send `selectRobot 1` and `halt` as two receives, and read `state` until TrajState is 0 or 1 (`Globals.gpl:118-129`). `NewRobNum` is applied at the next receive (`Main.gpl:98-123`), so one buffer would run `halt` on robot 0. The socket is closed before the call returns. `stop_robot` (`tcp_driver.py:399-409`) is not used. TrajState 2 and 15 are not halted. The package serves robot 1 only.

Safe state, one sentence: motion halted (TrajState 0 or 1) with power still on; the arm may hold or sag, and this package does not re-enable power, attach or home and offers no unpause. There is no `@reset`. A latched e-stop is not cleared by a device command. No power, attach, home, gripper, plate transfer, kinematics, ROS or camera command is served.

## Limits

Profile, each joint and speed are `Limit.operator_required`. `Cmd.gpl:116` shows the comparison with `1` and the name `N_PROF`. `Globals.gpl:82` sets `N_PROF` to 20. Those two numbers are not in one cited span, and one field cannot carry two limits, so the package does not declare a closed 1..20 profile limit. The example overlay's numbers are placeholders.

Profile is a count (`unit` `1`). Speed is a percentage (`unit` `%`) because `Cmd.gpl:532` calls the parameter a percentage; the number is not scaled and no range is declared. `tcp_driver.py:498`'s "0 - 100" is the client's comment, not a controller limit. Joint numbers use the dimensionless code `1` because a rotary axis is degrees and a linear axis is millimetres (`tcp_driver.py:486-488`), which are not one UCUM unit. The driver sends them unchanged. At most 12 angle parameters (`Cmd.gpl:1697`) is a schema bound. Fewer angles than `RobNumAxes` is a negative reply (`Cmd.gpl:1720-1726`), not a fixed six.

## Fail closed

An e-stop increments a generation counter under the stop lock before it connects, including when the halt later fails. Connect, `mspeed` and `MoveJ` replies, and the status-port exchange do not hold that lock, so a blocked `recv` cannot postpone `halt`. Cancellation, the e-stop epoch and that generation are checked again under the lock immediately before `mspeed` is sent and immediately before `MoveJ` is sent. The fence is set before `MoveJ`'s `sendall`. A cancel or e-stop during the `mspeed` reply sends no `MoveJ`.

`Cmd_Halt` is `Robot.RapidDecel` (`Cmd.gpl:1840-1842`) and does not clear the robot mailbox. The mailbox is set to Nothing after `Handler` returns (`Main.gpl:605-607`). The comm thread sends the reply only after that wait (`Main.gpl:207-209`, then `Main.gpl:225`). A complete MoveJ reply is that retirement. Until the reply arrives, the command can still start after TrajState reads 0 or 1. The stop sends `halt` and then fails, and it keeps the fence. It does not report the safe state, and it does not wait for the motion to finish. When the reply arrives the fence is cleared and the move outcome is unknown. A later halt reads TrajState again and can confirm 0 or 1. `Main.gpl:398` flushes pending serial input. It is not the TCP mailbox. A robot-port handshake does not share a lock with the status port. Each caller binds `port` on its own thread, which is what `connect_robot` reads (`tcp_driver.py:117`), and copies it before the handshake. Cancellation and publication of that socket share one lock, and the lock is not held across the handshake. If the wait expires first, the caller closes a socket that was already published. If the socket becomes ready after the wait was abandoned, the worker closes it and does not publish it.

One absolute deadline, `stop_confirm_s`, starts when the status halt starts and covers the connect, both sends, every reply byte and the TrajState polls. Setup rejects a non-finite value, a bool, and any value outside `(0, 15]`. The hardware factory accepts `stop_confirm_s` because the SDK passes every option into the factory, and it rejects `connect_timeout_s` or `read_timeout_s` above 15 s. It does not open a socket while checking those arguments.

A complete MoveJ reply clears the fence, including when a stop has already started. If the generation or the e-stop epoch changed, the move result is `OutcomeUnknown`. A negative `mspeed` reply does not send `MoveJ`. A connect that returns no socket, or a status port that refuses the connection, fails the stop (`MHS.SAFETY.SAFE_STATE_UNREACHED`). The driver does not send `enable_power` (the lab client does, at `pf400_driver.py:275-278`; this package does not). The lab client's state comment (`pf400_driver.py:307-315`) labels 0 as power off and 1 as stopping. The GPL labels Halted and Idle are `Globals.gpl:118-119`, and those are the ones this package uses.
