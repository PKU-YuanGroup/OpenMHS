# Action-backed ROS safety and Franka gripper contract

RosDriver supports an explicitly declared fixed action as an independent stop/safe-state path. ROS 1 actionlib and ROS 2 native profiles validate goal identity, terminal status, application success and the declared output schema before acknowledging safety. Action safety has its own bounded admission lane, separate from ordinary transactions. An accepted cancellation or a dispatched goal does not establish native completion or stopping.

Sent operations with uncertain outcomes remain owned. A valid late terminal releases capacity only after the original owner ended, while ordinary mutation remains fenced until explicit reset and a fresh stop. The finite safety history checks typed terminal fingerprints and fresh per-bridge goal identities. Contradictory or unverifiable old results leave a sticky safety fault. A result that changes between interpretation and retirement remains retained and returns unknown, including after an earlier success, failure or cancellation interpretation.

A historical fault permits bounded protective retries only after prior stop ownership and passive teardown ended safely. An unresolved or erroneous active stop, failed cleanup/lineage or unavailable connection still prevents another goal. Later retries never clear the historical fault, authorize motion/reset or report achieved=true. Pinned Franka handler and actionlib source support this narrow ownership distinction. It is not a guarantee for arbitrary action servers or physical stop latency.

The Franka ROS1 package keeps its selected gripper move, grasp, homing, stop and JointState surface. StopAction is now bound as the native safety route. Successful moves report submitted speed explicitly as a request receipt, not measured speed. A completed grasp with success=false reports grasped=false; an unsupported approach field is rejected before any goal. Operator-required limits remain independent of upstream API domains. This supersedes the previous ROS1 missing-action-route blocker; the separate Franka ROS2 reset/re-enable blocker is unchanged.

Independent private validation passes 203 ROS SDK tests without skips, 18 package cases, G1-G9 with no findings, and the exact retirement/protective-retry schedules. Earlier failed candidates and setup errors remain preserved in the private handoff evidence. The actual-tree G1-G9 gate and strict package collection also pass after integration. That deployment has no action-backed native safety server, so these live results do not establish StopAction behavior or physical stop latency. Fake package evidence remains contract_checked; human signature, native deployment validation and publication decisions remain separate.
