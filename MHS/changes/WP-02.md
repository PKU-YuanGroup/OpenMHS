# WP-02 — Catalogue, schemas and error registry (data contracts)

Findings addressed: SPEC-13 and SC-07 (schema namespace, x- extension rule),
SPEC-02 / SC-03 / DRV-02 / FIT-ROS-01 / SIM-01 (data half: typed, closed limit
rules keyed by limit paths), SPEC-10 (unsatisfiable or unenforced schema MUSTs,
too few examples), SC-04 / FIT-02 / FIT-07 / DRV-09 (verb in the manifest and the
generic `cap.device.configure.v1` write class), SC-05 (deprecated protocol
duplicates, experimental unused classes, resource-kind vocabulary), SC-06 (class
input bounds vs class limits, CAP-044 units maps), SC-08 (permit schema drift),
SC-10 / TESTS-11 (one error record shape, driver subset, unregistered
`MHS.HOST.JOURNAL_CORRUPT`), SC-11 (rpm and mix speed in `/min`), SPEC-05 /
TESTS-04 (expected_revision removed from class inputs), SURF-10 (generic
`MHS.HOST.ADAPTER_MISSING`), AF-02 / DRV-10 (reference file schema), AF-08
(endpoints file schema), SIM-07 (`fidelity.clock`), FIT-ROS-10 (`watchdog_ms`),
FIT-11 / REGQ-* (registry strategy and triage fields).

## What changed

### Schemas (`MHS/schema/`)
- Every `$id` is `SCHEMA_BASE + <file name>`
  (`https://openmhs.invalid/schema/0.9/…`); `$ref`s stay relative. Titles say
  OpenMHS. No schema or example mentions the legacy domain any more.
  `python3 MHS/sdk/tools/sync_data.py --check` now enforces the prefix (strict).
- `defs.schema.json`: new `$defs` `specVersion`, `verb` (read|write|invoke),
  `limitPath` (identifier segments joined by dots, each with optional `[*]` or
  `[N]`), `limitBound` (number or array of numbers), the **closed** `limitRule`
  `{min, max, allowed, unit, reason, source, ref, names, per}` (`source`
  vendor_doc|upstream_code|class_default|operator; vendor_doc/upstream_code
  require `ref`), `limitValue` (a rule or the string `operator_required`),
  `limitMap`, `packageId`, `commitSha`, `spdxExpression`, `licenseClass`,
  `pep440`, `dateOrDateTime`, `relPath`, `authoredBy`, `reviewedBy`, `gateId`,
  `blockedCode`, `factSource`.
- `device.schema.json` (additive only; no new required member):
  capability `verb`, typed `constraints` (`long_running`, `cancellable`,
  `max_duration_ms`, `concurrency`; other members still tolerated), binding
  `limits` and `safety.envelope` (`{capability pattern: limitMap}`) typed,
  `x-mhs-schema-digest` (CAP-037), `patternProperties ^x-` on the manifest
  root, resource entries and capability entries, optional `reference`
  (`reference.schema.json`), `fidelity.clock` (lockstep|free_running|external),
  `interlocks[].reset_exempt`, `interlocks[].required_for` items are capability
  patterns with `minItems: 1`, top-level `watchdog_ms`.
  (`safety.estop.latency_ms` already existed.)
- `capability.schema.json`: `status` stable|experimental|deprecated (pre-0.9
  `active` still accepted), `profile` core|sim, `examples` (validated inputs),
  `x-mhs-replaced-by` (CAP-040), `resource_kinds` may be `["*"]`, typed
  `limits`, `constraints.long_running`.
- `registry-record.schema.json`: `integration.strategy`
  (direct-driver|family-config|bridge-runtime|reference|skip|untriaged),
  `integration.role`, `integration.reason_code`, top-level `blocked_on`
  (blocked codes or `helper:<name>`-style prerequisites), `wave`, `rank`,
  `quarantine`, `variant_of`, `source {repo_url, commit, ref}`, `license_spdx`,
  `license_class`; `evidence.state` adds `contract_checked` and
  `hardware_checked`; `adapter.manifest_ref` may be null; `registry_id`
  accepts a DNS name or a single `<name>-registry` label (so `REGISTRY_ID`
  `openmhs-registry` is valid while the existing negative tests still hold).
- `conformance-report.schema.json`: `tests[].required`, `tests[].spec_ref`,
  `subject.manifest_digest`, `subject.source_commit`, `disclaimers` (see
  deviations).
- `permit.schema.json`: matches the live `mhs.safety.permit` result
  (`resource`, `single_use`, `scope.{device_id, capability_id, resource,
  input_digest, principal, expires_at, single_use}`, approvals without
  `permit_id`, `evidence` link).
- `adapter.schema.json`: `patternProperties ^x-`; the `devices` description no
  longer claims `instance_id` may be omitted (it contradicted device.schema).
- New: `reference.schema.json` (plan 3.4, closed at every level),
  `site-limits.schema.json` (narrow-only overlay keyed by device id, then a
  capability id → limit paths, or a parameter path → rule; every overlay rule
  has a bound and source operator), `driver-lock.schema.json`,
  `driver-result.schema.json` (RESULT.json; blocked/skip-proposed need
  `blocked_on`, pass needs a gate digest with no failed gates),
  `check-report.schema.json` (exactly one result per G1-G9; fake/sim backends
  can only yield `contract_checked`), `endpoints.schema.json`
  (`~/.mhs/endpoints.json`), `errors.schema.json`.
- Examples: `examples/valid/` (12 documents: two typed-limit device manifests,
  reference file, site overlay, driver lock, two results, check report,
  endpoints file, triaged registry record, conformance report with
  disclaimers, live-shape permit) and `examples/invalid/` (24 documents plus
  `expected-failures.json`, which gives each file's schema, JSON pointer and
  whether the failure is a schema error or a load-time (semantic) rule).
  Required kinds are covered: `maxx` typo, unknown rule member (`clamp`), array
  bound of wrong length, widening overlay (scalar and per-element), interlock
  with empty `required_for`, verb mismatch; plus misspelled limit path, bad path
  grammar, unit mismatch, envelope keyed by a field, operator_required inside an
  overlay, non-operator overlay source, and invalid reference/lock/result/
  check-report/endpoints/registry/conformance documents. The two pre-0.9
  examples keep validating (identifiers updated).

### Capability catalogue (`MHS/spec/capabilities.json`)
- New `cap.device.configure.v1` (verb write, risk floor R1, `resource_kinds:
  ["*"]`, open patch input whose effective schema is the writable
  state_schema properties of the bound resource, output `{applied, revision}`).
  63 classes; `capability_count` 63; `spec_version` 0.9.
- Every class has `status` and `profile`: deprecated (still valid, with
  `x-mhs-replaced-by`): device.describe → mhs.devices.get, world.state →
  mhs.resource.read, world.snapshot → mhs.snapshot, world.restore →
  mhs.restore, motion.estop → mhs.safety.estop, compute.cancel →
  mhs.operations.cancel; experimental: the other 13 of the 15 unused classes;
  `profile: sim` for the 7 world.* classes.
- One validated `examples` input per class; `expected_revision` removed from
  world.step, world.restore and motion.joint_position inputs; centrifuge
  `rpm`/`rpm_actual` and mix `speed` use `/min` (mix speed lost its
  dimensionless `maximum: 1`); aspirate/dispense/transfer `volume` maximum 1000
  uL and centrifuge `rpm` maximum 15000 (equal to the class limits), spectrum
  `wavelength_min` minimum 200 nm (the class limit); every `units` map equals
  its x-mhs-unit annotations (CAP-044; joint_position, joint_velocity,
  joint_torque, home, force_torque, imu and spectrum were missing array
  fields); top-level normative `resource_kinds` (51 kinds, with `see_also` for
  the overlapping synonyms); `since` rebased to 0.9.0.

### Error registry (`MHS/spec/errors.json`, `mhs/errors.py`)
- One record shape `{code, area, jsonrpc_code, retryable, status, since,
  meaning, remediation, driver_subset}` (+ `replaced_by` for deprecated codes),
  a top-level `areas` table (structural JSON-RPC codes per area, ERR-007), and
  `errors.schema.json`. Records are in registry order (area, then appendix
  order), so `_code_from_jsonrpc` keeps its first-match results.
- Added `MHS.SAFETY.LIMITS_UNSET`, `MHS.HOST.ADAPTER_MISSING` and
  `MHS.HOST.JOURNAL_CORRUPT` (emitted by the OpenAI4S integration but
  unregistered); `MHS.HOST.OPENAI4S_MISSING` is `deprecated` with
  `replaced_by: MHS.HOST.ADAPTER_MISSING` (still registered; it is not added to
  `LEGACY_ALIASES`, so `normalize_code` does not rewrite it).
  `MHS.CAPABILITY.EXPERIMENTAL_PRESENT` is now a `feature` record (ERR-008).
- `driver_subset: true` on exactly the 13 frozen codes.
- `mhs/errors.py`: the table between the BEGIN/END GENERATED markers is
  written by `MHS/sdk/tools/gen_errors.py` (`--check` fails on drift and on
  registry invariant violations). `ErrorSpec` gained `status`, `since`,
  `driver_subset`, `replaced_by` (defaults keep positional construction
  working); new exports `DRIVER_SUBSET`, `DEPRECATED_CODES`,
  `is_driver_code()`; `describe_error` reports status/driver_subset.
  `LEGACY_ALIASES` and `normalize_code` are unchanged.

### Appendices and tools
- `MHS/sdk/tools/gen_appendices.py` regenerates MHS-A (status and profile
  columns, deprecated table, resource kinds, inventory) and MHS-B (generated
  area table and one table per area including BRIDGE/HOST, the driver subset
  and the deprecated codes; the stray §3.18/§3.19 after §7 are gone; requirement
  text ERR-001..ERR-012 and MHS-A-001 kept). `--check` exits 1 on drift.

### Tests
- New `MHS/sdk/tests/catalog_data/` (49 tests): valid examples validate (schema
  and load-time rules), every invalid example fails at its expected pointer
  (semantic ones are schema-valid), class shape/status/profile/examples/units/
  limits/bounds, configure-class derivation, deprecated and experimental sets,
  resource kinds, error registry shape and generated module, driver subset,
  legacy aliases unchanged, generator freshness and stale detection, `$id`s,
  relative `$ref` resolution, legacy prefix still resolving, closed limit
  rules, reference endpoint manifests and the live permit validating.
  `_semantics.py` is a small test-only reference of the load-time rules a
  schema cannot express (limit path resolves, array bound length, unit matches
  field, verb matches class, overlay narrows).
- `tests/core/test_schema_examples.py` validates `examples/*.json` and
  `examples/valid/*.json` by file-name stem, the catalogue and errors.json.

## Behavioural changes
- Manifests with an unknown limit-rule member, an `operator_required` typo, a
  non-numeric bound, an envelope keyed by something other than a capability
  pattern, an empty `required_for`, or a verb outside read|write|invoke are now
  schema-invalid (conformance's manifest check reports them).
- `mhs.errors`: `MHS.CAPABILITY.EXPERIMENTAL_PRESENT` has no JSON-RPC code
  (feature string); `MHSError("MHS.HOST.OPENAI4S_MISSING")` keeps its code but
  its default message/remediation point at the replacement.
- `mhs.schema.get` / `GET /mhs/v1/schema/<name>` serve the new `$id`s.

## Compatibility notes
- No wire identifier changed. All device.schema additions are optional; the
  registry's 2,967 records and 1,967 manifests and every manifest the SDK test
  suite validates are still valid (checked with a validation log of the whole
  SDK and integration suites before/after: no new validation errors outside the
  new invalid examples). Legacy `$schema` URLs resolve through the WP-01 store.
- `status: active` is still accepted in class documents (chapter 03 examples).

## Deviations
- `limitRule` also accepts `per` (rolling_1h|rolling_24h|rolling_7d|session):
  the SAFE-004 cumulative-budget fixtures and the server's cumulative check use
  it, and the WP requires existing manifests and fixtures to stay valid.
- `conformance-report.disclaimers` is optional (when present it must contain
  `not_certified`): the conformance generator (WP-07) validates its own output
  and does not emit the field yet; making it required now would break every
  report. Flip to required once WP-07 emits it.
- 13 rather than 15 classes are `experimental`: `cap.motion.estop.v1` and
  `cap.compute.cancel.v1` are both unused and protocol duplicates; `status` is
  single-valued, so they are `deprecated`.
- `registry_id` accepts DNS names plus `<name>-registry` labels rather than any
  single label, so the registry's existing negative test (`registry` rejected)
  keeps passing while `openmhs-registry` validates.
- `since` is 0.9.0 for every class and code (the old 1.0.0 version line is
  retired with the rename).

### What changed
- `MHS/spec/capabilities.json`: `cap.thermal.setpoint.v1` inputs `tolerance`
  (`K`) and `rate` (`K/min`) carry `"x-mhs-delta": true`, so `mhs.units`
  never applies the Kelvin/Celsius offset to them (`catalog.merge_schema`
  inherits the marker into effective schemas). They are the only temperature
  differences in the catalogue; every `Cel` field is a level and stays
  unmarked (pinned by a test).
- One lifecycle vocabulary: the 141 `active` error records are `stable`, the
  word capability classes use. `errors.schema.json` enumerates
  `stable|deprecated|retired|feature` and still accepts `active` as the
  pre-0.9 spelling (as `capability.schema.json` does), so older copies keep
  validating; `gen_errors.py` refuses `active` and any other word in the
  registry itself. `mhs.errors.ErrorSpec.status` defaults to `stable`.
- `since` semantics: the OpenMHS specification release (MAJOR.MINOR.PATCH of
  `spec_version`) that registered a code / introduced a class in its current
  form; it is not the registry format and wire revision (`mhs_error_registry`,
  `mhs_capabilities` = `1.0`). Stated in `errors.schema.json`,
  `capability.schema.json`, the `ErrorSpec` docstring (which said "registry
  version") and both appendices; `gen_errors.py` refuses a `since` that is not
  a release or is later than `spec_version`.
- `MHS.HOST.OPENAI4S_MISSING` remediation now tells the receiving agent what
  to do (install OpenAI4S in the host environment or add its source tree to
  `PYTHONPATH`, or disable the integration; handle it like
  `MHS.HOST.ADAPTER_MISSING`, which replaces it in 0.10) instead of telling the
  emitter which code to emit.
- `device.schema.json` `safety.estop.native` (optional, string 1..128
  non-blank, or null): the native stop the runtime calls, which the reference
  renderer publishes as `safety.estop.native`. `reference.schema.json`: the
  same constraints on `safety.estop.native`, and measures may carry `inputs`
  (field descriptors of the optional parameters of a read-verb measure, see
  WP-03.md).
- Examples: `device.thermal-bath.json` names its bindings with `x-mhs-name`
  (`set_temperature`, `measure_temperature`, `heater_off`) and declares
  `safety.estop.native: "stop"`; `reference.thermal-bath.json` is now exactly
  `reference_file.render(device.thermal-bath.json, site-limits.json, facts,
  tags, provenance)` minus the two provenance digests (they change with every
  catalogue edit). That brought in what the hand-written file had left out:
  the measure's optional inputs, the class summaries, the four narrowed
  lines, `actual_temperature` in the outputs, `requires_permit`, and risk R2 for
  `heater_off` (the device risk class is a floor).
- `gen_appendices.py`: appendix A explains `since` and `x-mhs-delta`;
  appendix B explains the lifecycle words, `since` and that remediation
  addresses the receiving client. Both appendices regenerated;
  `sync_data.py` re-run (`--check` OK).
- Tests: `tests/catalog_data/test_followups.py` (8 tests: delta markers,
  lifecycle words, `active` still schema-valid but refused by the generator,
  `since` vs `spec_version`, actionable remediation on the wire, e-stop
  `native` in the device schema); `test_errors.py` expects `stable` for
  `MHS.HOST.ADAPTER_MISSING`.

### Behavioural changes
- `mhs.errors.MHS_ERROR_CODES[code].status` and `describe_error(code)["status"]`
  say `stable` where they said `active`. Nothing on the wire changes (status is
  not part of error objects).
- `MHSError("MHS.HOST.OPENAI4S_MISSING")` carries the new remediation text.
- A manifest may declare `safety.estop.native`; an empty or blank string is
  schema-invalid.

### Compatibility notes

  that compared error status with `active` must compare with `stable` (none in
