## Milestone 07a (tolerant suite, in-process harness)

### What changed

New modules under `MHS/sdk/src/mhs/conformance/` (stdlib only):

- `model.py` — `LEVELS`, `PROFILES`, `ENDPOINT_PROFILES`, `TestOutcome`,
  `TestCase` (now with `group` = base/OP/SAFE/FID, `actuation` =
  none/negative/effect, `post`, `always_required`), code normalisation.
- `synth.py` — test inputs. `bindings_for(manifest)` resolves every binding
  (catalogue verb, permit, deprecation, and the effective limits through
  `mhs.catalog.compile_manifest_limits`, i.e. class ∩ binding ∩ envelope incl.
  patterns; legacy manifests fall back to the server-style merge). Inputs come
  from a fixture file, then class `examples` projected onto the binding's
  fields, then envelope-aware synthesis (element-wise bounds, defaults, enums,
  `multipleOf`); `pattern`/`format` strings are never invented
  (`Unsynthesizable` → the test skips with the reason). `alternate_input`
  builds a distinct valid second input or returns `None`. `envelope_probes`
  builds a value just outside each declared bound (inside the schema range when
  possible) for every limited path, array element and allowed set.
- `inprocess.py` — public `Loopback` transport, `client_for(server)`,
  `Harness` (records every bridge call by shadowing the bridge's contract-plane
  methods on the instance; injects interlocks forced `open`/`unknown`,
  cooperatively cancellable delays, dropped responses after the effect, and
  raising calls), `run_suite_inprocess(factory, profile, level, **options)`
  (fresh endpoint for the read-only checks and for each mutating group), and
  `reference_factory(name, **options)`.
- `static.py` — manifest-only checks: `TCON-001` profile vs subject kind,
  device modes and manifest `conformance.profile` (CON-004/005); `CAP-035`;
  `CAP-017` risk floor; `CAP-016` drift incl. limit widening (CAP-018) and
  `TCAP-002` kind mismatch via `mhs.catalog.resolve_binding` (both advisory in
  07a); `SAFE-045` (hardware/hybrid R2+ needs `kind: hardware`, a
  `physical_ref` or a non-empty `achieved_by`); `SAFE-029` (`achieved_by`
  resolves to bound, permit-free actions; non-empty for hardware); suite
  self-checks `CON-031` (no hardware actuation without opt-in; in-process the
  recorder proves zero bridge write/invoke calls) and `CON-032` (e-stop/reset
  only for `software`/`both` e-stops).

### Behavioural changes

- Levels can drop for drivers that relied on SDK behaviour: a null driver is ≤
  CL1; a no-op e-stop fails CL3 (`SAFE-028`); garbage output fails CL2
  (`TCAP-001`); a binding that lowers its class risk floor fails CL0
  (`CAP-017`).
- Hardware/hybrid subjects without `allow_actuation` are capped at CL1 and no
  write/invoke reaches their driver (as corrected in fix round 2: in-process
  the harness blocks it at the bridge, over a plain client negative tests are
  not sent); replay never caps hardware.
- Over a plain client, CL3 needs a way to open the declared interlocks (an
  in-process run or the conveyor test hooks).
- Reference fixtures under suite 1.2.0, in-process (`run_suite_inprocess`):
  conveyor (normal and test profile) CL4, arm CL4, lab CL2 (`SAFE-029`: the
  plate reader's `achieved_by` names `cap.motion.stop.v1`, which it does not
  bind). Over a plain client: conveyor test profile CL4, conveyor normal CL2
  (no way to open `door_closed`), lab CL2, arm CL4. Three in-process runs on
  fresh instances give identical verdicts for conveyor, lab and arm.
- `run_suite`, `cases_for_level` raise `ValueError` for unknown or
  unsupported profiles/levels instead of coercing them.
- `python -m mhs.conformance` exits 5 (was 2) below the required level and the
  required level defaults to the claimed one; usage errors exit 2.

### Compatibility notes

- `run_suite(client, profile, level)` keeps its signature; the new options are
  keyword-only. `TestCase(...)` positional arguments are unchanged.
- The published reports (suite 1.1.0) still validate and their levels
  recompute; strict report rules apply to suite ≥ 1.2.0 reports only.
- The suite works against the current server and the plan 3.6 semantics: it
  accepts `INPUT_INVALID` or `ENVELOPE_VIOLATION` for out-of-range probes,
  an unchanged revision when the state hash did not change, refused resets
  when not latched (cleanup only), legacy cancellation outputs, and finds an
  operation through `operations.list` when an unknown receipt carries no
  handle.

## Milestone 07a — verification fix round

The independent verification of 07a failed on two major issues; this round
fixes both and the cheap minor ones. Each verifier repro was ported as a test
first and failed on the pre-fix package (the CL0 and report tests were run
against the verifier's pre-fix copy, `scratch/verify-WP-07/07a/hybrid04`, with
stub names): 10/20 report and CL0 tests, 15 failures + 3 errors in the gate,
harness and inventory tests.

### What changed

- **A CL0 claim can fail** (major; CON-018, CONF-04, item (7)). The report
  schema has no "none" level, so a report whose required CL0 tests did not pass
  keeps `level_achieved: CL0` as its floor but now leads `limitations` with
  `NO LEVEL ACHIEVED: required CL0 test(s) did not pass: ...`
  (`report.CL0_NOT_ACHIEVED`, `cl0_blockers`, `cl0_limitation`).
  `report.level_awarded(report)` returns `None` for it (exported from
  `mhs.conformance`). `semantic_errors` rejects a strict report that hides the
  failure (or states it falsely). `compare_reports` reports a
  `level awarded` mismatch. The summary prints `achieved=none` and
  `no level achieved: CL0 is blocked by ...`. `python -m mhs.conformance` exits
  5 for it, also for `--level CL0`, and treats any blocked level at or below the
  required one as below target. `verify` prints `no level achieved`.
- **The hardware gate no longer fails open on SAFE-011's hook path** (major;
  CON-031, item (6)). Over a plain client, `SAFE-011` invokes
  `x-cap.mhs-test.set_door.v1` (and resets afterwards) only when
  `ctx.may_actuate(device)`, which is true when `allow_actuation` is set or the
  device is neither hardware nor hybrid. Otherwise it skips with the CON-031
  reason. In general, `SuiteContext.invoke` records every command that a
  hardware/hybrid device without `allow_actuation` dispatched instead of
  refusing. A dispatched command is any receipt other than `rejected` that is
  not a replay and is not a read-verb binding. These records go into
  `RunLog.hardware_dispatches` as (test id, device, capability, status), and
  `CON-031` fails on any, naming the test.
- **TCAP-001** (minor). Fails a probe whose output is empty (`{}`/`None`) while
  the class requires output fields. A skeleton binding `output_schema`
  inherits the class output (as in `mhs.catalog.resolve_binding`), and no binding
  waives a required class field. This catches null drivers behind invoke
  classes with a permissive output schema. Non-empty mismatches with the class
  output stay an advisory note, because the reference fixtures still drift.
- **SAFE-014** (minor). Accepts only `MHS.SAFETY.ENVELOPE_VIOLATION`
  (`LIMIT_EXCEEDED`) or `MHS.CAPABILITY.INPUT_INVALID` (legacy
  `MHS.SCHEMA.INVALID_INPUT`). `INVALID_PARAMS` and other `MHS.SCHEMA.*` codes
  no longer count. Every binding-targeted command now passes
  `resource=binding.resource`: `SuiteContext.invoke` resolves it when the
  (device, capability) binding is unique, and the probe, envelope, interlock,
  permit, cancellation and replay call sites pass it explicitly (plan 3.6
  step 3, WP-04 4d). A duck-typed client without the parameter is retried
  without it.
- **Uninstrumented bridges fail closed** (minor). `Harness.uninstrumented_for
  (device_id)` lists the actuating methods (`call`, `write`, `restore`) that
  could not be shadowed. For a hardware device without opt-in, `CON-031` then
  becomes `skip` (inconclusive; required at CL0, so no level is awarded). The
  in-process "no bridge call" checks of `SAFE-011`, `SAFE-012` and `SAFE-014`
  fail, naming the methods.
- **Report checks** (minor). A report is validated strictly when its
  `suite_version` is ≥ 1.2.0, its `report_version` is ≥ 1.1.0, or it contains
  any test id that suite 1.1.0 lacked (`report.SUITE_1_1_TEST_IDS`), so
  downgrading the version string no longer relaxes validation. Strict endpoint
  reports must carry `subject.manifest_digest`. `compare_reports` now also
  compares `suite_version` and `report_version`, and treats a missing digest on
  a strict report as a mismatch.
- **Traceability** (minor; CONF-07/CONF-11). `TCAP-001` and `TCAP-002` check
  no numbered requirement (`[]`). They cite their spec text from a new
  `sections` map in `traceability.json` (MHS-003 §3 `output_schema` /
  `resource_kinds`), and `spec_ref` uses it. `CAP-007` is `not_verified`
  again. Regenerated inventory counts: executable 52 → 51, not_verified
  266 → 267, 580 ids.
- **Interlock and cancellation evidence** (minor). `SAFE-011`/`SAFE-012` fail
  when the device is latched before the probe, and an injected interlock must
  be refused with `INTERLOCK_OPEN`; `ESTOP_ENGAGED` is accepted only on the
  hook path, when opening the door is what latched the device. The hook path
  also closes the door when `safety_status` raises. In-process, the `OP-011`
  detail states that the harness delay stood in for the native call.
- Docs: `docs/conformance.md` (exit 5 on a failed CL0, the no-level rule, the
  hook gate and dispatch recording, the resource rule, the fail-closed
  recorder, the SAFE-014 codes, TCAP-001, the interlock rule, strict-report
  detection, verify comparisons, the TCAP sections). `docs/reports/README.md`

### Compatibility notes

- `level_achieved` keeps the schema enum. Consumers that need to tell "CL0
  failed" from "CL0 passed" use `level_awarded()` or the leading limitation.
- The published suite 1.1.0 reports (report 1.0.0, 1.1.0 ids only) still
  validate leniently.
- `SuiteContext.invoke` accepts `resource=`. `run_suite` and

### Deviations

- CAP-016 still does not report a skeleton binding `output_schema` as
  widening. `mhs.catalog.resolve_binding` (WP-03) defines it as inheriting the
  class output, so TCAP-001 enforces the inherited output instead.
- TCAP-001 makes the class output required only for empty outputs. All three
  reference fixtures return non-empty outputs that do not match their class
  output: the class realignment is post-pilot, and requiring it would drop them
  to CL1.
- CON-031 for an uninstrumented hardware bridge is `skip` (inconclusive), not
  `fail`; nothing is known to have reached the device.
- `validate_report` also requires `subject.manifest_digest` on strict endpoint
  reports; the hint asked only for `compare_reports`.

## MERGE-B fix round (after the independent MERGE-B verification)

The MERGE-B verifier kept two 07a harness defects as majors. On the merged
tree they were masked only by the stronger WP-04 endpoint. It also flagged
the mixed-mode session minor. Each was ported as a test first, failed on the
merged tree, then was fixed.

### What changed

- **Blocker/major: hardware-gate attribution for a shared bridge**
  (`conformance/inprocess.py`).
  - **The problem.** `Harness._instrument` wrapped a bridge object once and
    fixed the device id at wrap time. A hardware device served by a bridge
    first reached through a simulated device was then recorded under the
    simulated id, and its calls passed `_refuses()` while
    `blocks(hardware)` was true. With an endpoint that did not enforce the
    envelope, the negative tests moved the hardware arm.
  - **The fix.**
    - The harness keeps `id(bridge) -> [device ids]` (`_sharing`) and wraps a
      shared bridge once.
    - Each wrapper resolves its target per call (`_target`): the device that
      `ctx.device_id` names when it shares the bridge (`snapshot(device_id)`
      too). Without one, a shared bridge records its first hardware device
      (fail closed: CON-031 then sees the call).
    - `_refuses()` blocks an actuating call when **any** device sharing the
      bridge is hardware or hybrid, whichever device the call names. A
      read-verb `call` passes only when it is a read of each of those devices.
    - Methods that could not be shadowed are listed for every sharing device.
- **Major: wrappers that were never installed** (`conformance/inprocess.py`).
  After `setattr`, a wrapper counts as installed only when
  `getattr(bridge, name) is wrapper`. A `__setattr__` that silently drops or
  forwards the write, or a class-level data descriptor, is now listed in
  `Harness.uninstrumented`, so `blocks()` is false and the negative tests are
  not sent to such a hardware bridge.
- **Minor: mixed-mode endpoints** (`conformance/tests_core.py`).
  - **The problem.** `SuiteContext.ensure_session()` opened one session for
    every device with `mode=None`, and the endpoint gave it the last device's
    mode. Commands to a device of the other mode came back
    `MHS.SESSION.MODE_MISMATCH`, and SAFE-014, OP-005, PROTO-027 and SAFE-011
    or SAFE-012 reported that as a required failure.
  - **The fix.** `ensure_session(device_id=None)` opens one session per device
    mode when the modes differ; the primary mode's session is still
    `ctx.session_id`. Reads, commands, e-stops, resets, permits and
    `operations.list` use the session of their target device's mode.
    `operations.get` and `operations.cancel` use the session that started the
    operation (`ctx.operation_sessions`). A single-mode endpoint behaves as
    before.
- **Minor (MERGE-B follow-up): TSAFE-001 wording.** When the endpoint refuses
  `mhs.safety.reset` (for example a strict hardware endpoint's
  `MHS.AUTH.FORBIDDEN`, operator only), the detail now names the receipt
  status, code and reason instead of "still engaged after a *successful*
  reset". The verdict is unchanged.
- **Docs** (`docs/conformance.md`):
  - shared bridges are gated as hardware;
  - the install check;
  - per-mode sessions;
  - the SAFE-028 black-box limit: a driver that overrides `estop()` with a
    no-op, declares a no-op `achieved_by` and reports no safe state passes.

### What changed

- **Blocker: SAFE-014 no longer passes with a limited path unprobed**
  (CONF-06, DRV-02 / FIT-ROS-01; verifier `h_unsynth.py`,
  `i_allowed_pattern.py`). `synth.envelope_probe_plan(binding, base, *,
  base_error=None)` now returns a `ProbePlan` with `gaps` (new `Gap(limit_path,
  path, reason)`) and `not_applicable` besides `probes`/`unprobed`:
  - a limited binding without a valid base input (a required `pattern`
    string with no fixture or class example) makes every applicable limited
    path a gap (`base=None`);
  - a path or element without a buildable out-of-limit value is a gap: an
    allowed set on a `pattern` string that no candidate matches, an allowed
    set on a `format` string, an array element the suite cannot build;
  - a binding (or envelope, or published) limit on a field the binding's
    input schema does not declare is a gap;
  - only a class-default limit on an undeclared field is not applicable (a
    note). This covers the lab's `cap.fluid.*` `volume` and
    `cap.measure.spectrum.v1` `wavelength_min`, so its level is unchanged.

  `tests_core.safe_005` makes SAFE-014 **skip** while any gap is uncovered,
  naming each path and reason and asking for "a fixture (valid /
  out_of_envelope)". A probe that was sent and found a violation still fails
  the test. A fixture's `out_of_envelope` inputs are now sent even without a
  valid base input. A gap counts as covered only when a fixture refusal names
  it: its concrete path, or its limit path when the gap is the whole path.
  A synthesized probe at another element of the same path never covers it.
  New `synth.limit_path_of` maps a refusal's concrete path to the limit path.
- **Allowed sets on pattern strings are probed** (`i_allowed_pattern.py`).
  The suite tries same-shape mutations of an allowed value (per position, same
  character class, then appended or dropped characters). It sends the first
  one that the pattern and the field schema accept, for example `gear='loa'`
  for `^[a-z]+$` and `[low, mid]`. When none matches, the path is a gap. A
  `format` string never gets an invented value. Plain strings also use a
  schema-valid candidate when one exists and otherwise keep the former
  out-of-schema `mhs-conformance-not-allowed` value. Booleans are probed with
  the other value.
- **Major: array tails under a wildcard** (`m_wildcard_tail.py`).
  `synth._element_paths` expands each wildcard of a limit path
  (`points[*].z`) to the first and the last element of its array. An array
  the path names keeps "every element of a vector bound, first and last under
  a scalar bound", and nested arrays below it expand the same way. The last
  element is the fixed length (`minItems == maxItems`, or `prefixItems` with
  `items: false`). Otherwise the array is grown to at least two elements when
  `maxItems` allows, so a first-element-only endpoint fails also on
  variable-length arrays. `_ensure` grows an array with copies of its last
  element where the item schema is shared (no `prefixItems` entry, no
  `uniqueItems`) and the copy is within the limits. Synthesis is the fallback,
  so a fixture element with a `pattern` string still yields a tail.
- **Major: no silent probe budget** (`j_tail_budget.py`). The 32-probe cut
  (`_MAX_PROBES`) is gone. Every probe of an element is mandatory: both sides
  of the bound and the allowed set. Elements are taken breadth-first (the
  first element of every limited path, then the next ones) up to
  `_MAX_PATH_PROBES` = 256 elements per binding. Elements beyond that stay in
  `ProbePlan.unprobed`, and SAFE-014 skips with the budget reason, as before.
- **Minor: OP-001 checks extension reads** (TESTS-04; `k_ext_read.py`).

  uncatalogued id) that declares `verb: read`. A compatibility-mode manifest

  `SuiteContext._fill_declared_verbs` takes it from the hello device
  summaries into the new `Binding.declared_verb`. Ordering: the probe's
  device first, catalogued before extension. Such reads are sent only to
  devices the suite may actuate, because an extension's verb is the driver's
  own claim.
- **Hardening (CON-031)**: the in-process gate (`Harness.gate`
  `read_capabilities`), the over-the-wire send guard and the CON-031 dispatch

- `synth._legacy_bounds` records the source label of each bound
  (`binding`/`class`/`envelope`) so that the not-applicable rule also works
  for manifests the runtime compiler refuses.
- Docs: `docs/conformance.md` (harness gate reads; OP-001 read-only line;
  Inputs; the SAFE-014 paragraph on element expansion, pattern mutations,
  mandatory probes, gaps, fixture coverage and the not-applicable rule; the

### Behavioural changes

- SAFE-014 skips (required at CL3, so the level stops at CL2) instead of
  passing with a note in these cases:
  - a limited write/invoke binding has no valid base input;
  - a limited path or element has no buildable out-of-limit value;
  - a non-class limit sits on a field the binding does not declare.

  It fails as soon as a sent probe is accepted. Driver authors supply
  `valid` / `out_of_envelope` fixtures for such bindings.
- SAFE-014 sends more probes: both sides and the allowed set at every
  element, first and last elements under wildcards, and two elements of
  variable-length arrays. Endpoints that check only some elements or one side
  of a bound fail where they used to pass.
- OP-001 fails an extension read (declared `verb: read`) that advances the
  revision. A read-only simulated endpoint whose only reads are extensions
  now has a required OP-001: its first read must complete. Before, OP-001 was
  skipped as having no probe.
- On hardware/hybrid devices without `--allow-actuation`, extension reads are
  neither sent by OP-001 nor let through by the in-process gate or the send
  guard.

### Deviations

- For an allowed set on a `pattern` string the verifier's hint was to skip.
  The suite first tries in-schema mutations of an allowed value and skips
  only when none matches the pattern. This gives more coverage and never
  sends a value the field schema rejects. It is the one place where a
  `pattern` string is built (WP-07 detail (3) forbids inventing them for
  valid inputs; this is a negative probe checked against the pattern).
- Variable-length arrays are grown to two elements when `maxItems` allows.
  The hint only said to take the length from the schema or the base. Without
  this, a one-element synthesized base would still hide a
  first-element-only endpoint.
- Extension reads are held to OP-001 only on devices the suite may actuate,
  and the hardware gate trusts only catalogued reads. Both go beyond the
  minor's hint, as CON-031 defence in depth.
- A non-class limit on an undeclared field is a gap (skip), not a note. The
  runtime refuses to construct such a device, so only third-party endpoints
  can publish it.
