## SDK

`mhs.driver.ros_compose` (new) resolves a `compose` object. The keys are `kind` (`topic`, `service` or `action`), `deployment` (one key matching `[a-z][a-z0-9_]{0,31}`), `expression` (`getName()` or one identifier; bare `getName` is refused), `literal` (one absolute string literal) and `place` (`suffix` is value + literal; `prefix` is literal + value). A binding has `compose` or a literal endpoint, and it does not also carry `source_name`. The module does not import `families`, `sensed_stop` or `ros_check`. It is in the gate's internal module lists (`check.py` `_GATE_INTERNALS`, `_GATE_MODULES`, `_CORE_MODULES`) and is not part of the public driver export.

`expression_shown` tokenises the cited text in one left-to-right scan. `//` and `#` skip the rest of the line, and `/*` skips through `*/`. A quoted string and a C++ raw string are one token, so a comment delimiter inside either string stays string content and text that only contains the expression does not prove it. Compound operators (`==`, `!=`, `<=`, `>=`, `&&`, `||`, shifts, and the assignment forms) are one token. A single `=` bounds an assignment. `?` and `:` do not, so a comparison or a conditional arm does not prove the endpoint. The literal may be quoted or wrapped once in `std::string`, `string` or `str`. A method call or a subscript on either operand fails (`std::string("/cmd_vel").substr(1)`, `"/cmd_vel"[0]`), as does `->` before the expression. Parentheses may group the concatenation. Another `+` inside or outside those parentheses fails (`(_namespace + "/cmd_vel") + suffix`, `prefix + (_namespace + "/cmd_vel")`). An identifier matches a whole token, so `_namespace` does not match inside `my_namespace`.

Round 2. Stripping comments before the scan accepted `const char* a = "/*"; const char* b = R"x(*/"; _namespace + "/cmd_vel";)x";`, because the concatenation lives only inside the raw string. Splitting `==` into two `=` tokens accepted `n.subscribe((_namespace + "/cmd_vel") == unused ? "/actual" : "/other", 1, cb);` while the called topic is the other arm. Both are `ROS_COMPOSE_EXPRESSION`. A concatenation that follows a string containing those delimiters, and an assignment with one `=`, still count.

Round 3. The first escape in a string cleared the escape flag, so `const char* a = "\t\"; _namespace + '/cmd_vel';";` closed at the next quote and the concatenation was read as code. Every backslash now consumes the next character. One escape makes that token ineligible as the declared literal. A backslash at the end of the text or immediately before a newline, and a quote that never closes, are not scanned as code. A `//` or `#` line that ends in a backslash and a newline keeps the next physical line inside that comment or directive. A comma separates arguments only when the parenthesis that encloses it is a call, as in `n.subscribe(_namespace + "/cmd_vel", 1, cb)`. The comma operator does not: `n.subscribe((_namespace + "/cmd_vel", "/other"), 1, cb)` discards the concatenation, and `return` and `sizeof` are not calls. All three reviewer lines are `ROS_COMPOSE_EXPRESSION`. A closed escaped string followed by a real subscribe, a comment that does not continue, and `n.advertise<nav_msgs::Odometry>(getName() + "/odom", 10)` still count.

Round 4. Treating every `>` before `(` as a template call accepted `n.subscribe(flag > (_namespace + "/cmd_vel", 0) ? "/other" : "/actual", 1, cb);`. The concatenation is the discarded left operand of a comma operator, and the call receives `/other`. A `>` or `>>` is a call only when it closes a template argument list that opened on an identifier and names a qualified type (`::` inside the list). `flag > (` has no matching `<`. `a < b > (` has no qualified type. `advertise<nav_msgs::Odometry>(` and a nested `std::map<std::string, nav_msgs::Odometry>` still count. Splicing every physical line before the raw string is recognised turned `R"x(raw )x\` at the end of a line into the closing delimiter and exposed `_namespace + "/cmd_vel"` that exists only inside that string. The buffer is not spliced. A raw string is consumed on the physical text, so a backslash-newline stays in its body. A `//` or `#` line still continues on its own span, and a quoted string still splices a backslash-newline inside that string. Both reviewer lines are `ROS_COMPOSE_EXPRESSION`. The three round-3 lines stay rejected.

`resolved_name` accepts a deployment value of one ROS segment, with or without one leading slash. The literal is an absolute path of one or more segments. The concatenation must already match an absolute ROS name. `"/robot0" + "odom"` is `"/robot0odom"` and is accepted. `"robot0" + "/cmd_vel"` is relative and is refused. No slash is inserted. A prefix is accepted when that concatenation is already absolute.

Round 1. `_target` omitted `compose`, so a reset and a re-enable with the same composed binding compared empty and the driver constructed. Reset then called the re-enable. The guard now treats an identical compose declaration as one target before a value exists, and, once deployment names are known, compares the absolute names, including a literal mixed with compose. `bridge_config` and `simulation_deployment` both refuse that pair before a transport is opened (SAFE-042, CORE-086). Two bindings whose resolved names differ are not refused.

A composed action (`compose.kind` is `action`) takes the same profile check as a literal `action` key. ROS 1 requires `ros1-actionlib`. ROS 2 requires `ros2-native`. The mismatch is a definition error before native I/O.

`endpoints_can_match` is fail-closed for a sensed-stop collision. Two suffix topics match when their literals are equal. A suffix compose topic can match a fixed topic when some one-segment value reproduces that fixed name. Prefix, mixed places, and a non-string literal can match (the declaration is refused). Two fixed topics match only when they are equal. A non-topic compose against a non-topic does not match.
