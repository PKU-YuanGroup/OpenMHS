# WP-05 — Bridges and pilot family runtimes

Findings addressed: SIM-03 (Gymnasium/MuJoCo bridges cannot drive their
families under the class contracts), FIT-09 and LAB-02 (no async, Status or
property support in the python-object bridge; SCPI templates inexpressible),
DRV-06 (a scalar native return cannot be mapped; misspelled result paths give
empty outputs), FIT-ROS-08 (bridge half: result targets checked against the
output schema), FIT-08 (lab instruments and long tail: `%` and compound units,
async, timeouts), FIT-ROS-07 (unit table), DRV-11 / FIT-ROS-11 / LAB-08
(grammar flipping on key presence, silent legacy clamp, undocumented return
contract), DRV-03 (bridge half: e-stop, reset, interlocks and safe state never
reach a declarative native API), FIT-04 (no SCPI bridge), REGQ-02 / SIM-02 /
TESTS-01 / OSS-04 (bridge half: `python -m mhs.bridge.<x>` exits 0 silently),
SDK-14 (bridge half: `remaining_ms` ignores the context deadline and crashes on
`deadline_ms=None`), SC-06 (clamp shapes, bridge half). FOLLOWUPS items for
WP-05 from WP-02 and WP-03 are all applied (units from `mhs.units` with a
compatibility re-export, explicit-factor fallback through `UnknownUnitError`,
clamps through `mhs.limits`, native timeouts as `mhs.signals.OutcomeUnknown`,
strict error rules through `mhs.errors.is_driver_code`).

## What changed

### `mhs/bridge/base.py` -- contract, units, limits, AsyncRunner
- The module docstring and `Bridge` docstrings state the Bridge contract:
  `call()` returns the capability output dict (never an `{output, state}`
  wrapper); state leaves only through `read()`; outcomes are raised
  (`mhs.signals.Cancelled`, `DriverFailed`, `Busy`, `OutcomeUnknown`);
  `estop()` may run concurrently with a call and never takes `self._lock`.
- Units come from `mhs.units`: `convert_unit` is a re-export (`delta=` keyword
  added), `UnitError` is `mhs.units.UnitError`, the local table is gone (a
  read-only `_UNITS` view derived from `mhs.units` remains for compatibility).
  `_unit_spec` derives every conversion, checks an explicit factor/offset
  (rel. 1e-9), treats an explicit `offset: 0` between absolute temperature
  scales as a temperature difference, and keeps the ADPT-021 explicit-factor
  fallback for codes outside the UCUM subset (catches `UnknownUnitError`).
  `convert_unit(50, "%", "1") == 0.5`; `{"from": "%", "to": "1", "factor": 0.01}`
  now compiles (it was refused).
- Every clamp (canonical or legacy, with or without an `envelope`) is compiled
  by `mhs.limits.compile_limits` (`compile_clamp`) and checked by
  `mhs.limits.check` (`check_clamp`): out of range is
  `MHS.SAFETY.ENVELOPE_VIOLATION` (details `{target, path, kind, bound, value,
  source, envelope}`), never a silent clamp; malformed bounds are load errors.
- `get_path`: `output`, `output.$`, `result`, `$` name the raw native value;
  `result.` and `$.` prefixes are stripped like `output.`.
- `FieldMapping(required_by_default=, optional=)`: canonical result maps fail
  on an absent native path instead of dropping the field.
- `ErrorMap(strict=True)` restricts codes to `mhs.errors.DRIVER_SUBSET`.
- Signals that are also `MHSError`s (so the 0.9 compatibility server and a
  server using `mhs.signals.outcome()` classify them the same):
  `BridgeFailed(DriverFailed)`, `BridgeBusy(Busy)`,
  `BridgeOutcomeUnknown(OutcomeUnknown)`, built by `driver_failed()`,
  `busy()`, `outcome_unknown()`.
- `AsyncRunner`: one persistent event-loop thread per bridge (lazy);
  `run(awaitable, timeout_ms=, cancel_event=)` uses
  `run_coroutine_threadsafe`, cancels the task (`future.cancel()`) and raises
  `Cancelled` when the cancel event is set, cancels and raises an unknown
  outcome when the bound expires, and propagates the native's own exceptions.
  `wait_future`, `wait_status` (Status-like: `wait(timeout)` in slices, else
  `done`/`success`; cancel through `cancel()`/`stop()` when available),
  `call_bounded` (sync native bounded on a daemon thread -> unknown outcome)
  and `resolve_native`; `Bridge.async_runner`, `Bridge.resolve_native()`.
  `Bridge.close()` closes the loop.
- `BridgeContext.remaining_ms()` honours `extra["deadline_at"]` and no longer
  crashes on `deadline_ms=None`.
- New hooks: `Bridge.estop_native` (native stop symbol/command, `None` =
  software-only), `Bridge.safe_state(ctx)`.
- `format_command` (one-line templates; string arguments with control
  characters or a separator such as `;` are `INPUT_INVALID`) and `parse_text`
  (`raw|str|float|int|bool|regex`).
- `unsupported()` raises `MHS.CAPABILITY.NOT_BOUND` (the legacy alias it used
  normalised to the same code); `load_object` reports configuration errors as
  `MHS.ADAPTER.MANIFEST_INVALID` and no longer echoes factory exception text.
- `main()` prints `use: mhs serve <driver-dir|mhs-adapter.json>` and returns 2.

### `mhs/bridge/python.py` -- PythonObjectBridge
- The canonical MHS-006 grammar is the default for `config["capabilities"]`
  (`bridge` defaults to `python-object`; an entry's `resource` key is taken
  out of the inner binding). The key-presence heuristic is gone; the
  deprecated in-process shape needs `"grammar": "legacy"` (DeprecationWarning;
  legacy entries are now closed). A binding of another bridge family is a
  manifest error.
- `invoke`: `call` (awaitables, futures and Status-like returns are awaited),
  `get`/`set` (property getter/setter), `await`, `status`, `query`/`write`
  (`command` template + optional `parse`). Async `setup`/`close` hooks and an
  async factory are awaited on the bridge's loop.
- `result.map` with `output`/`output.$` maps a scalar return
  (`{"temperature": "output.$"}` -> `{"temperature": 22.0}`); an absent
  mapped path is `MHS.CAPABILITY.OUTPUT_INVALID`; with
  `capability_schemas={cap: {"output_schema": ...}}` targets the (closed)
  output schema does not define are refused at load and its optional targets
  may be absent.
- Native timeouts are `OutcomeUnknown` (`MHS.OUTCOME.UNKNOWN`, not retryable)
  instead of a retryable `MHS.OUTCOME.TIMEOUT`; awaits are bounded by
  `min(timeout_ms, ctx.remaining_ms())` and cancelled with `ctx.cancel_event`.
- `bindings_ref` (path relative to `base_dir=`); declaring the document twice
  is refused. `strict=True` (or config `strict`) restricts error codes to the
  driver subset, also for documents.
- `safety_bindings {estop, safe_state, reset, interlocks[]}` map to native
  calls (constants only, bounded, never under `self._lock`): `estop()` runs
  the e-stop then the safe-state native (any failure ->
  `MHS.SAFETY.SAFE_STATE_UNREACHED` signal), `safety_status()` reports
  `safe_state.achieved` (read by the server after an e-stop), `interlocks()`
  reads `closed|open|unknown` (unreadable or non-boolean = unknown), `reset()`
  is refused (`MHS.SAFETY.INTERLOCK_OPEN`) while an interlock is not closed.
- `writes` gains a per-parameter form (`params: {name: {native, invoke,
  type|unit|clamp...}}`, every value mapped and checked before the first
  native call, unknown keys -> `MHS.RESOURCE.NOT_WRITABLE`); `write()` returns
  `{"applied": {...}}` and `cap.device.configure.v1` is routed to it when no
  explicit binding exists (and advertised in `capabilities()`).
- Mapped native exceptions are `driver_failed()` signals; unmapped ones stay
  `MHS.ADAPTER.SHIM_FAILED` with a redacted message.

### `mhs/bridge/bindings.py`
- Hand validator: `invoke` (`INVOKE_FORMS`), `command` (one line, plain fields
  that are declared arguments; only with `query`/`write`), `parse`
  (`PARSE_KINDS`), `get` takes no arguments, `set` exactly one.
- `strict=` on `validate_binding`, `normalize_binding`, `load_bindings`
  (driver-subset error codes; also re-checks an already-loaded document).
- Normalised entries carry `invoke`, `command`, `parse`. Helpers
  `parse_spec_errors`, `command_template_errors`, `template_fields`.

### `mhs/bridge/serial.py`
- Closed config and capability keys; timeouts and interrupted waits are
  unknown outcomes; transport write failures are `DEVICE.FAULTED` signals; the
  input buffer is flushed before each transaction; string arguments cannot
  inject commands.
- `safety_bindings`: e-stop/safe-state commands are written under a short
  write lock (never the transaction lock) and abort a pending response wait;
  `reset` (response read by default), `interlocks` (query + parse +
  `closed_when`; unknown when the transaction lock is busy past its bound).
- `writes` per-parameter form and the configure route; `reads.fields`.
  `FakeSerial.reset_input_buffer()`.

### New `mhs/bridge/scpi.py` -- ScpiBridge
- Transports: `SocketTransport` (stdlib socket, sliced bounded reads,
  `interrupt()`, stale-response discard after a timeout), `VisaTransport`
  (lazy `pyvisa`, `visa_backend` e.g. `@sim`), or an injected transport
  (transcripts). `*IDN?` probe on connect (`idn.expect` regex -> NOT_READY on
  mismatch). Command map `{resource, query|write, args, parse, result, opc,
  timeout_ms, errors, check_errors}`; optional `error_query` (`SYST:ERR?`)
  mapped through ordered error rules; `reads.fields`, `writes.params`,
  configure route, `safety_bindings` (write commands; interlock queries).

### New `mhs/bridge/transcript.py`
- `Transcript` (load/dump/from_json/to_json, `send`/`receive`/`exchange`,
  `assert_complete`, `rewind`), strict replay raising `TranscriptDivergence`
  (an `AssertionError`) on any order/content divergence, exhaustion or a read
  without a recorded response; `line_transport()` (SCPI), `serial()`
  (pyserial-like, for `SerialBridge(serial_factory=...)`), `http()`
  (`request(method, path, body)`), `recorder(live_transport)`.

### `mhs/bridge/gymnasium.py`
- `cap.world.step.v1 {ticks, action}`: loops `ticks`, stops at a terminal
  state unless `autoreset=True`, refuses a step after the end of an episode
  (`DEVICE.PRECONDITION_UNMET`), returns `{observation, reward (sum), terminated,
  truncated, tick, state_hash}`; the first step without a reset starts the
  first episode. Space-derived actions/observations: `Discrete` -> `{index}`,
  `Box` -> `{values}` (per-element limits from `low`/`high`, published in
  `capabilities()` with the derived input schema), `Dict` -> named fields,
  `MultiDiscrete`/`MultiBinary` -> `{values}`, `Tuple` -> `{items}`. Input is
  checked structure -> limits (`ENVELOPE_VIOLATION`, zero env steps) -> rest of
  the schema. `seed` -> `{seed, accepted}`; `reset` -> `{observation, seed}`.
- Snapshot/restore through `get_wrapper_attr` / `unwrapped`
  (`get_state`/`set_state` or `get_state_dict`/`set_state_dict`), including
  the episode bookkeeping; determinism `exact` only when supported.
  `cap.world.render.v1` is unbound. Advertised: step, reset, seed (the
  deprecated `world.state/snapshot/restore` stay callable).

### `mhs/bridge/mujoco.py`
- `step {ticks, action: {ctrl}}`: `ctrl` checked against
  `actuator_ctrlrange`/`actuator_ctrllimited` (limits generated from the model
  and published) before `data.ctrl` is written; `n_steps` is a deprecated
  alias. Integration-state snapshots with `mj_getState`/`mj_setState`
  (`mjSTATE_INTEGRATION`), fallback copy with `snapshot_exact = False`.
  `mujoco` is imported lazily (also on the prebuilt path; `mujoco=` injects a
  module) -- a prebuilt model without mujoco is `NOT_READY`, not an
  `AttributeError`; the time step comes from `model.opt.timestep`.

### `mhs/bridge/replay.py`, `mhs/bridge/__init__.py`
- Every bridge module (`base`, `bindings`, `python`, `gymnasium`, `mujoco`,
  `serial`, `scpi`, `transcript`, `replay`) has `main()` + a `__main__` guard
  printing `use: mhs serve <driver-dir|mhs-adapter.json>` and exiting 2.
- `__init__` exports `AsyncRunner`, `ScpiBridge`, `Transcript`,
  `TranscriptDivergence`; `available_bridges()` adds `scpi` and `scpi-visa`.

## Behavioural changes
- `%` converts as 0.01; compound units convert; a wrong explicit factor is a
  load error.
- No clamp ever truncates: legacy clamps and canonical clamps inside a wider
  envelope now reject with `ENVELOPE_VIOLATION` before the native call.
- `config["capabilities"]` is canonical by default; the old shape needs
  `"grammar": "legacy"`. SerialBridge/ScpiBridge configs are closed.
- Native timeouts and unanswered serial/SCPI requests are `MHS.OUTCOME.UNKNOWN`
  (not retryable) instead of a retryable `MHS.OUTCOME.TIMEOUT`.
- Canonical result maps: `output`/`output.$` is the raw return; an absent
  path is `OUTPUT_INVALID` (was a silently missing field).
- Output mapping failures are `MHS.CAPABILITY.OUTPUT_INVALID` (was
  `MHS.SCHEMA.INVALID_STATE`); mapped native errors are `DriverFailed`
  signals that are also `MHSError`s with the same code as before.
- Cancellation before/inside a native call raises `mhs.signals.Cancelled`
  (was an `MHS.OUTCOME.CANCELLED` error); the 0.9 compatibility server records
  it as a failed receipt until WP-04 adopts the signal.
- `write()` returns `{"applied": {...}}`.
- Gymnasium/MuJoCo outputs follow the class schemas (`tick`, `state_hash`,
  object observations); `n_steps` is deprecated; render is unbound.
- `python -m mhs.bridge.<x>` exits 2 with the usage line.

## Verification fixes (second WP-05 step)

The independent verification of WP-05 failed on one blocker and one major
issue; this step fixes both and the cheap minors, all inside WP-05's files.
The verifier's probes (`scratch/verify-WP-05/probes/p1_clamp.py`,
`p2_targets.py`, `p3_paths.py`, `p5_misc.py`, `p6_psu_server.py`) were ported
first as `MHS/sdk/tests/bridges/test_verification_regressions.py` (30 tests;
before the fix: 41 failures and 4 errors across the tests and subtests).
After the fix every probe gives the safe result.

### Blocker: `get_path` root words after a prefix (regression of this WP)
- `base.get_path` stripped one prefix and then re-tested the root words, so
  `input.output`, `input.result`, `input.args`, `input.input`,
  `output.result`, `output.output` named the whole value.  Through
  `MHSServer` an `{output: false}` request passed the whole input dict to
  `set_output` (truthy) and the PSU output went ON in a `completed` receipt.
- Now: a path that is exactly `""`, `$`, `input`, `output`, `args` or
  `result` is the whole value; one `input.`/`output.`/`args.` prefix is
  stripped, after which only `$` (or nothing) is the whole value
  (`output.$`).  `result.` and `$.` are no longer prefixes: `result.x` is
  `obj["result"]["x"]` again (as in the 0.8 baseline).
- Legacy grammar compatibility: `"grammar": "legacy"` result paths
  `result.x` / `$.x` (which read the native return through the 0.8
  `{result, $}` wrapper) are rewritten to `output.x` when the entry is
  compiled (`python._legacy_result_spec`), so legacy maps keep their meaning.
- Tests: `GetPathRegressionTests` (every root word after every prefix, the
  `result.`/`$.` baseline meaning, boolean `false` reaches the native typed
  and untyped) and `PsuEndToEndTests` (through `MHSServer`: `output=false`
  switches the PSU off; `output.result` maps the `result` field; legacy
  `result.`/`$.` paths).

### Major: clamp/envelope `unit` accepted but ignored
- A clamp is checked after the rule's unit conversion (in the native unit
  for args, in the MHS unit for results).  `compile_clamp(..., unit=)` now
  compiles against `{"value": {"type": "number", "x-mhs-unit": <to unit>}}`
  and passes the clamp/envelope `unit` into the `mhs.limits` rule: a unit
  other than the conversion's `to` unit, or two disagreeing declared units,
  is a load error (`MappingError` -> `MHS.ADAPTER.MANIFEST_INVALID`); a clamp
  unit after a legacy `scale`/`offset` is refused (it cannot be checked).
  `{max: 500, unit: "mm"}` on an mm -> m argument is refused at load; the
  matching `{max: 0.5, unit: "m"}` rejects 1000 mm.  Violation details carry
  `unit`.
- The hand validator mirrors it (`bindings._clamp_unit_errors`): inline
  `args[x].clamp` and `result.map[y].clamp` against their own `unit`, and
  binding-level `clamp` entries against the target's inline or binding-level
  `units` conversion.
- Tests: `ClampUnitTests`.

### Minors fixed
- Output contract (FIT-ROS-08, WPS (4)): with `capability_schemas`, result
  targets the output schema's `properties` do not define are refused whenever
  `properties` exist, unless the schema is explicitly `x-mhs-open: true` (a
  missing `additionalProperties: false` no longer opts out).  A map that
  leaves a required output property unmapped is refused at load, except
  `revision` (the server adds it) and `sampled_at`, which the bridge stamps
  with the time the native returned when the schema requires it and the map
  does not produce it (12 measure/sensing classes require `sampled_at`, which
  a native getter cannot return).  `validate_binding` and `FieldMapping`
  refuse inverted result maps (`"$"`, `"$.x"`, `"output.x"`, `"input.x"` as
  output field names).  Tests: `OutputContractTests`.
- Transcripts: a recorded `recv` that was never read is a
  `TranscriptDivergence` at the next request and in `assert_complete()`;
  `"recv_optional": true` on an exchange allows a device answer the bridge
  ignores.  Tests: `TranscriptStrictnessTests`.
- Interlocks: `closed_when: true` (the default) only matches a boolean, so
  serial/SCPI interlocks with a non-`bool` parse (default `str`) and

### Blocker: interlocks failed open on a malformed reply
- Parse kind `bool` read every token except `1`/`ON`/`TRUE` as `False`, so
  an inverted interlock (`closed_when: false`, e.g. `DOOR:OPEN?`) read
  `ERR`, an empty line or `-113,"Undefined header"` as *closed*.  Through

  `true` token (default `1`) or `ON`/`TRUE`.  `False` is the new `false`

  `MappingError`.  Helpers: `base.bool_tokens()`, `BOOL_TRUE_TOKENS`,
  `BOOL_FALSE_TOKENS`.  Effects:

    `MHS.SAFETY.INTERLOCK_OPEN`;

### Major: e-stop ordering race on serial and SCPI
- Serial: `_transact` re-checks the e-stop epoch under `_write_lock`,
  immediately before `serial_obj.write`.  `estop()` advances the epoch
  before it takes that lock, so a command either precedes the e-stop
  command on the wire or is refused with `MHS.SAFETY.ESTOP_ENGAGED`.  The
  input flush now has its own error path ("serial input flush failed").
- SCPI: a new bridge `_wire_lock` is held only while one request line is
  written.  It is shared by `_write_safety` (e-stop and safe-state writes)
  and by `_put_request`, which re-checks the epoch inside it.  As a result,
  a query is a write under the wire lock plus a read outside it whenever the
  transport has `read`:
  - `SocketTransport.begin_query()` keeps the stale-response discard;
  - a transport that only has `query` runs the whole exchange under the
    wire lock.

  Transport failures map exactly as before (`_transport_failed`), and an
  `ESTOP_ENGAGED` refusal is never turned into an unknown outcome.

### What changed

- **Blocker: a numeric interlock read an error reply as `closed`.**
  - **The problem.** For parse kinds `int` and `float`, `parse_text` used
    `re.search` and took the first number found anywhere in the reply. With
    `closed_when: 0`, `'ERR 0'`, `'E0 unknown command'` and `'0,"No error"'`
    read closed; with `closed_when: 1`, `'E1 bad'` and `'ERR 1: bad command'`
    did. `reset()` then ran, and through `MHSServer` the reset and the next
    actuation completed (`HEAT 1` on the wire). This is the same fail-open
    class as the round-2 `bool` blocker. The serial, SCPI and python-object
    bridges were all affected.
  - **The fix.** `parse_text(text, spec, *, whole=False)` gained `whole=True`:
    `int`, `float` and `regex` then use `re.fullmatch` (the default number
    pattern, or the declared `pattern` anchored at both ends), so the stripped
    reply must *be* the value. Anything else raises `MappingError`, and the
    interlock reads `unknown`, which blocks the reset.
    - `serial.interlocks()` and `scpi.interlocks()` call it with `whole=True`.
    - The python-object bridge marks every compiled interlock call
      (`_Call.whole_reply = True`), and `_perform` passes it to `parse_text`.
  - Capability and state reads keep the lenient first-number parse
    (`'V=3.2 V'` still reads 3.2).
  - Docstrings (serial, SCPI, python) and the load-error wording ("declare
    closed_when as the whole reply's value") were updated.
- **Minor (round 3): nested `Dict` action spaces were unbounded (Gymnasium).**
  - `_field_schema` recurses into a nested `Dict` (an object with
    `required` and `additionalProperties: false`) and describes a `Tuple`
    field as an array with its item count. `action_limits()` emits a rule per
    nested member (`action.arm.j`). `_native_field` converts nested `Dict`s
    and `Tuple`s.
  - Dicts nest at most 8 deep; a deeper `Dict` member is refused by the
    schema (`{"not": {}}`), never passed unbounded.
  - `Tuple` elements, top level or inside a `Dict`, still get structure but
    no limits. This simulation-only residual is now stated in the module
    docstring.
- **Minor (round 3): the SCPI interrupt window.** `SocketTransport.read()`
  cleared the e-stop interrupt flag when it started, so an `interrupt()` that
  landed between a query's write (under the wire lock) and its read was lost,
  and the read waited its full timeout. The flag is now cleared in
  `begin_query()`, when a request starts.
- **Minor (round 3): SCPI wording.** The module docstring now says no
  *actuating* request follows the e-stop command. A write that was already on
  the wire still sends its `*OPC?` and `error_query`; neither actuates.
