User decision 3 of `work/handoff-runs/claude-20261104/user-decisions-20261105b.json` allows both relaxations when the basis is stated. This record implements them and then applies them to three packages. Where the basis is not shown, the package stays blocked.

1. Version evidence by inference. The only closed rule is `ros1-noetic-from-catkin-and-python3`. A package-side item is `{side: "package", inference, basis: [{ref, shows}]}`. `shows` is `catkin` once and `python3` once. `catkin` is a non-comment `<buildtool_depend>catkin</buildtool_depend>` element or `find_package(catkin ...)` outside a comment and outside a string argument. XML comments, hash comments, and CMake bracket comments (`#[[ ... ]]`, `#[=[ ... ]=]`), including one opened on an earlier line, do not show it. A quote or an apostrophe inside an ordinary `#` comment is ignored, so it cannot hide a later bracket comment. A quoted argument (`"find_package(catkin REQUIRED)"`) and a bracket argument (`[[ ... ]]`, `[=[ ... ]=]`) do not show it. A `find_package` hit is a CMake command whose name is exactly `find_package` and whose first package argument is exactly `catkin`: an unquoted word, or one quoted or bracket argument whose content is `catkin`. `message(find_package(catkin REQUIRED))`, `my_find_package(catkin REQUIRED)`, `find_package("Boost" catkin)`, `find_package([[Boost]] catkin)`, and `find_package(catkin-extra REQUIRED)` do not show it. Quoted and bracket arguments keep their boundaries, so masking one cannot move a later argument into the package position. `python3` is the interpreter of the first line of the file, `python3` or `python3.N`. A later line does not show it. A `python` or `python2` interpreter does not, and neither does a later `python3` token (`#!/bin/sh # python3`, `#!/usr/bin/env echo python3`). `/usr/bin/env` accepts only `-S`, `--`, and `-u` / `--unset` / `-C` / `--chdir` with one following argument. `--help`, `--version`, and any other option do not run the interpreter (`#!/usr/bin/env --help python3`). A basis line that names another ROS distro fails that basis. The rule does not scan the rest of the clone. A passing inference implies ROS 1 distro `noetic` and is stored as an inference. It is not a line that states Noetic, and it does not imply a Gazebo major. A `ros2-noetic-...` profile does not match. The companion side still needs the distro in a cited range. An unknown id, a companion-side inference, or a token on an inference item fails closed. On any other profile the gate says the inference implies distro `noetic` for ROS 1, not that profile.

2. A `type_ref` of a binding that is not the e-stop, its read-back or the re-enable may cite a declared companion only when that companion is local, at its pinned commit, and version-matched. Gate G7 re-checks the version evidence itself. The cited line must still show the declared message type. `source_ref` and `state_ref` of those bindings stay `ROS_COMPANION_SCOPE`. A type citation that is not version-matched is `ROS_COMPANION_TYPE_UNMATCHED`.
