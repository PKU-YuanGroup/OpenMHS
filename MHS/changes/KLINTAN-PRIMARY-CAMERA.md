# Klintan USB camera primary image and calibration observations

OpenMHS is not affiliated with, endorsed by, or a reimplementation of Anthropic's MHS research preview.

The existing Klintan ROS2 USB-camera package previously exposed only a frame-id string and remained blocked on its missing primary image. This local review repair uses the existing SDK image-artifact path to retain every BGR8 sample and its exact ROS2 header, and adds a complete independently captured CameraInfo output. The original resource/action and every original assertion remain.

The finite root-namespace profile binds `/image` and `/camera_info`; the source creates the relative `image` publisher despite the README's `/image_raw` wording. The supplied `/camera` launch needs an explicitly reviewed graph/remapping to this profile. Independent subscriptions do not prove synchronization, producer freshness, calibration validity or physical capture. Camera startup settings and external compressed-image republishers are not fabricated as device control endpoints.

Controlled package tests decode a complete nonconstant 1280x720 BGR8 frame, verify all calibration matrices and ROI fields, malformed/nonfinite refusal, header association, row padding, receipt replay, session/principal/TTL authorization and cleanup. A separately run host test verifies full MCP image retrieval. An explicitly selected 4 MiB artifact allowance admits the full sample; the default 2 MiB allowance rejects it with no grant. Cancellation before endpoint closure retains its terminal receipt. Endpoint closure ends evidence recording immediately and is tested for failed-worker retirement and no artifacts, matching the existing SDK contract.

The stock G1-G9 fake gate passes with the existing SAFE014_NOT_APPLICABLE CL2 note; there is no numerical actuation envelope to invent. No unsourced or binary citation is accepted. The package retains its original DeepSeek author, task/source pin and null human signature. The initial package-only candidate tests provide contract_checked evidence: those tests started no USB camera, upstream executable, native dependency, ROS graph or hardware backend. The repair changes no SDK or family enablement; parent integration subsequently regenerates registry metadata and synchronizes package cards. The historical metadata-only acceptance/blocker and all failed author test attempts remain preserved privately for review.

Independent review accepted twenty package tests, one complete MCP test and three additional controls, all nine gates and strict single-package collection. A subsequent isolated Docker run captured genuine controlled ROS2 Image and CameraInfo messages, then replayed the unchanged decoded messages through the exact candidate's fake backend and stock RecordingRosTransport. It verified all 2,764,800 pixel bytes, the complete 2,766,428-byte PNG resource, separate headers, all calibration fields and original receipt replay. The explicit 4 MiB store admitted the sample; the unchanged default 2 MiB store refused it without grants. Container, fixture, tunnel, child processes and stores were cleaned. This staged evidence does not admit the candidate as a live/native camera backend and does not prove physical calibration, freshness or synchronization. The fixed-root namespace still requires deployment review.
