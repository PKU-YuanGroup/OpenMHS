# Four blocked packages re-authored: SQUAD AD75019 switch, LTAMP PyBullet PR2, Galago OT-2, scanning SQUID microscope

Four packages that the blocked-package triage sent to re-authoring (class D of `TRIAGE-2.json`, with scanning-squid's recon route) are rewritten by Claude and pass the gate: gh.squad-lab/qcdrivers (a decorated driver that reports each route, reads it back with the firmware's `STAT?` and drains both `*RST` lines), gh.caelan/ltamp (the PyBullet `PBController` path, whose world advances only inside driver calls), gh.sciencecorp/galago-tools (the pack's OT-2 tool, re-selected by a routing override, with a run stop confirmed by a status read through a bounded port of its client) and gh.moler-group/scanning-squid (the repository's primary device, the scanning SQUID microscope, served for its Attocube positioners, the actuators with a stop). One routing file replaces two override entries. No SDK, spec or schema file changed.

## Packages

### gh.squad-lab/qcdrivers (R1, hardware; AGPL-3.0, publish review required)

A decorated direct `Driver` over the card's entry `qcdrivers.squad.mux.mux:Muxi` (the earlier PythonObjectDriver
result map could not report the route sent: G8 TCAP-003). Every command goes out with the upstream handle's `query`
(the call `send_command` makes, mux.py:86) and further lines are read with its `read` (as `printconfig` does, mux.py:171),
one exchange at a time under a lock; `send_command`, `switch32` and `reset` are not called (their retry path raises
AttributeError on a VISA timeout, mux.py:87-90; `reset` reads one of the two `*RST` lines). Served: connect
(`SWITCH32 x,y`, the firmware's "Route added 32x32", then `STAT? x,y` read back: x, y, the reply and the 32x32
route-buffer bit), status (`STAT?`, R0), reset (`*RST`), an identity read (`*IDN?`), and the e-stop (`*RST`, confirmed
only when "Reset complete" follows "Clear complete", firmware.ino:51-56, at most four lines read). A connect holds the
line lock across `SWITCH32` and its read-back and checks for cancellation under it first, so the e-stop's `*RST` never
falls between or before them; the reset action checks for cancellation under the same lock before its `*RST`. The
e-stop declares a latency of 5000 ms. The read-backs are the firmware's route buffers, not the analog switches. Pins
are `operator_required`. The fake emulates the clone's firmware sketch line by line.

### gh.caelan/ltamp (R1, simulated, fake-only)

A decorated direct `Driver` over the override entry `control_tools.pb_controller:PBController`, the controller
`ROSWorld(sim_only=True)` builds (plan_tools/ros_world.py:15-38); the earlier package drove the retired real-PR2
`ROSController`. Served: both arms through `cap.motion.joint_position.v1` (bounded by the PR2 soft limits of
control_tools/common.py; the four roll joints are continuous), the torso lift joint as a written and read-back state
field, and the arm angles. ROSWorld switches real-time simulation off (ros_world.py:27) and, with
`execute_motor_control` false, a command sets joint positions without stepping the physics (pb_controller.py:145-146).
The e-stop sets `execute_motor_control` false and reads it back; every command refuses to run while it is set,
because the motor-control loops step the physics inside the call and check for no stop, and makes its cancellation
check and kinematic set under a lock the e-stop also takes. The stop covers this endpoint's calls only: another holder
of the same world could still step it. Fake-only (a decorated driver has one fidelity contract for all its backends;
this one describes the fake).

### gh.sciencecorp/galago-tools (R2, hardware)

A decorated direct `Driver` over `tools.opentrons2.driver:Ot2Driver`. Served: run an operator-approved protocol file
(upload, create, play; the path is `operator_required`, an allowed set), stop the run (the safe-state action), and reads
of the run id and status. The e-stop and the safe-state action send the run action `stop` (driver.py:175-181) unless
the run already reads succeeded, stopped or failed, and read the status until it does, for at most 8 s; the run is not
deleted (`cancel_protocol` deletes it right after the stop request, 184-190). `play` is sent under the stop lock after
a cancellation check, so an e-stop never runs between them. The upstream's requests have no timeout (except
`get_run_status`, 30 s), and the class inherits `ABCToolDriver.__getattr__`, which answers any missing name with a
no-op (tools/base_server.py:28-34): the hardware backend (native.py) is a port of `Ot2Driver` with the upstream's names
and requests, a connect and a read timeout on each, and one method of its own, `stop` (the first request of
`cancel_protocol` alone); gate G7 reports it `MAYBE_ABSENT`. The pack's own OT-2 gRPC server leaves the `Ot2Driver`
construction commented out (tools/opentrons2/server.py:24-27). A created run that was never played is stopped like any
other; whether the robot server accepts that stop is not shown in the clone (a refusal fails closed).

### gh.moler-group/scanning-squid (R2, hardware)

The repository controls one instrument, a scanning SQUID microscope; the native is
`microscope.susceptometer:SusceptometerMicroscope`, the class its documentation constructs (docs/pages/microscope.rst:4)
with the repository's `scanning-squid` directory on the path (docs/pages/workflow.rst:15); the earlier package served
the warm-up heater supply through a module the clone does not have (G7.NATIVE_NOT_FOUND). Of the microscope's two ways
of moving the SQUID, only the Attocube positioners have a stop (`atto.stop`: `stop n`, then mode `gnd`,
instruments/atto.py:143-152); the piezo scanner's ramps run in a DAQ output task created and awaited inside `goto`
(scanner.py:159-168) and cannot be stopped, so they are not served. Served: Attocube step (`atto.step`, then the mode
read back; `steps` `operator_required`), ground (the safe-state action) and the e-stop (`atto.stop` for z, x and y,
then every mode read back as `gnd`), and reads of the scanner position and the axis modes. A step checks for
cancellation under the lock the stop takes; a stop that runs while a step is in flight reports itself unconfirmed
(the upstream step may set its axis to `stp` after it, atto.py:167-169), and the runtime keeps the latch and re-runs the
stop until no step is in flight. A step that raises stops and grounds its axis and is an unknown outcome. The step
count is a request: the upstream writes the step command twice (instruments/atto.py:109-124, 168-169), and what the
ANC300 does with the second copy is not in the source, so an operator measures a command's steps before setting the
limit. Opening the hardware backend moves the scanner to [0, 0, 0] V (scanner.py:61), which native.py and RESULT.json
state.

## Self-review

After the first full collect run, a self-review found that in three packages an e-stop landing between an action's
last cancellation check and its native command could be confirmed before that command reached the device (a
`SWITCH32` after the `*RST`, a kinematic set after the flag was cleared, a step after the axes were grounded). Each
action now checks for cancellation under a lock the e-stop also takes (the server cancels operations before it calls
the native stop), and scanning-squid's stop additionally reports itself unconfirmed while a step is in flight. The
galago-tools run action had this guard for its play request from the start. Four package cases (one per guard, and
one that lets a step's commands arrive after the first stop and checks that the confirming re-run stops that axis
again) kill a mutant that removes the guard. No digest moved.

## Found, not fixed

- By design the stable gate digest covers the report (gate statuses, findings, backend, pin, SDK version), not the
  package's files: the new scanning-squid package prints the digest the earlier heater package printed while it still
  passed (`sha256:84423a06...`), so an unchanged digest is not evidence of an unchanged package.
- G7 treats a class with `__getattr__` in its bases as open (`MAYBE_ABSENT` for any name that occurs in the clone);
  for `ABCToolDriver` subclasses that `__getattr__` makes any missing method a silent no-op at run time.
- G7 for an explicit `pyfile:` class selector refuses every nested call (`atto.stop` is recorded as `atto.stop`, not a
  member), so a Station-like native whose work is done by components can be checked only through a dotted module
  name; the dotted name here is the upstream's own (its documented path entry).
- A decorated `Driver` cannot declare fidelity per backend (only family drivers have `fidelity_by_backend`), so a
  decorated simulator with both a fake and a live backend cannot describe both honestly; LTAMP stays fake-only.
- A hardware driver cannot add a gap to its fake view's fidelity contract (the SDK serves a fixed one and refuses a
  `fidelity` object on a hardware driver, `mhs/driver/model.py:578-580`), so a known gap of a hardware package's fake,
  such as scanning-squid's step count, can only be stated in prose.
- Upstream: scanning-squid's `setup.py` names a package directory the checkout does not have; galago-tools' OT-2 server
  does not construct its driver; qcdrivers' `Muxi.status` sends a command its firmware does not register and its retry
  path calls an undefined attribute.
